Chapter 33

Merge Sort and Quick Sort

Chapter 18 sorted boards by hand, one comparison at a time: bubble, selection, insertion. All three crawl on a big pile, because they do work that grows like the pile squared. Now the foreman drops a thousand boards on site and wants them in length order before lunch. The trick every fast sorter uses is the same one a good site manager uses: do not sort the whole pile yourself. Split it, hand each half to a mate, and deal only with joining their two sorted halves at the end. Split enough times and each mate holds one board, which is already sorted. That idea, called divide and conquer, is what turns a squared-time crawl into an n log n sprint.

Divide and conquer is a three-step plan for a problem too big to swallow whole:

  • Divide: split the problem into smaller problems of the same shape.
  • Conquer: solve each small problem (usually by splitting it again, until it is tiny enough to be trivial).
  • Combine: stitch the small answers back into the answer for the whole.

Both sorters in this chapter follow that plan on a list. They differ only in where they put the hard work. Merge sort splits blindly down the middle and does its real work in the combine step, merging two sorted halves. Quick sort does its real work up front, partitioning the list around a chosen value, which leaves nothing to combine.

Merge sort, step by step. To sort a list:

  • If the list has 0 or 1 elements, it is already sorted; stop. This is the base case that ends the splitting.
  • Otherwise split it into a left half and a right half.
  • Merge sort the left half. Merge sort the right half. (Each half splits again, all the way down to single boards.)
  • Merge the two sorted halves into one sorted list.

The picture below sorts 38 27 43 3. The top half of the drawing splits the list down to singles; the bottom half merges the singles back up in order.

The merge is the heart of it. Merging takes two lists that are each already sorted and walks them with two fingers, one on the front of each. Compare the two fingered values, copy the smaller into the output, and advance that finger. Repeat until one list runs out, then copy whatever is left of the other. Because both inputs are sorted, the smallest unused value is always under one of the two fingers, so one pass does it.

Here is merge on its own: it takes two sorted arrays and returns one sorted array holding all their values.

#include <iostream>
#include <vector>

// Merge two already-sorted vectors into one sorted vector.
std::vector<int> merge(const std::vector<int>& a, const std::vector<int>& b) {
    std::vector<int> out;
    out.reserve(a.size() + b.size());
    size_t i = 0, j = 0;            // one finger on each list

    while (i < a.size() && j < b.size()) {
        if (a[i] <= b[j]) out.push_back(a[i++]);
        else              out.push_back(b[j++]);
    }
    while (i < a.size()) out.push_back(a[i++]);   // leftovers from a
    while (j < b.size()) out.push_back(b[j++]);   // leftovers from b
    return out;
}

int main() {
    std::vector<int> left  = {3, 27, 38};
    std::vector<int> right = {9, 43, 82};
    std::vector<int> both = merge(left, right);

    std::cout << "merged: ";
    for (int v : both) std::cout << v << ' ';
    std::cout << std::endl;          // merged: 3 9 27 38 43 82
    return 0;
}

Wrap that merge in the divide-and-conquer plan and you have a full merge sort: split, sort each half, merge.

#include <iostream>
#include <vector>

std::vector<int> merge(const std::vector<int>& a, const std::vector<int>& b) {
    std::vector<int> out;
    size_t i = 0, j = 0;
    while (i < a.size() && j < b.size())
        out.push_back(a[i] <= b[j] ? a[i++] : b[j++]);
    while (i < a.size()) out.push_back(a[i++]);
    while (j < b.size()) out.push_back(b[j++]);
    return out;
}

std::vector<int> mergeSort(const std::vector<int>& v) {
    if (v.size() <= 1) return v;                 // base case: already sorted
    size_t mid = v.size() / 2;
    std::vector<int> left(v.begin(), v.begin() + mid);
    std::vector<int> right(v.begin() + mid, v.end());
    return merge(mergeSort(left), mergeSort(right));
}

int main() {
    std::vector<int> data = {38, 27, 43, 3, 9, 82, 10};
    std::vector<int> sorted = mergeSort(data);

    std::cout << "sorted: ";
    for (int v : sorted) std::cout << v << ' ';
    std::cout << std::endl;          // sorted: 3 9 10 27 38 43 82
    return 0;
}

Build it

Save the listing as mergesort.cpp, then compile and run:

g++ -std=c++17 mergesort.cpp -o mergesort && ./mergesort

Count the layers in the split picture: a list of n splits in half about log₂(n) times before it hits singles, and each layer merges every one of the n values once. That is n work per layer times log n layers, so merge sort runs in O(n log n) in every case, best, average, and worst. The cost is memory: the merge builds a fresh list, so it needs O(n) extra space.

Quick sort, step by step. Quick sort also divides, but it sorts in place and does its work before the recursion, not after:

  • If the list has 0 or 1 elements, stop. Base case again.
  • Pick one value as the pivot.
  • Partition: rearrange the list so every value smaller than the pivot sits to its left and every value larger sits to its right. The pivot is now in its final sorted position.
  • Quick sort the left part and the right part. No combine step is needed, because the parts are already on the correct sides of a settled pivot.

What is the pivot? The pivot is the reference value you compare everything against in one partition pass. Think of the foreman grabbing one board off the pile and saying "shorter than this goes left, longer goes right." That one board is the pivot. After the pass it sits exactly where it belongs in the final line, and the two piles either side get the same treatment. Which board you grab (first, last, middle, or random) does not change the answer, but it decides how balanced the two piles are, and that decides the speed.

The partition (Lomuto scheme). Take the last element as the pivot. Walk an index i that marks the boundary of the "smaller than pivot" zone. Scan j across the rest: each time arr[j] is below the pivot, grow the zone by one and swap that value into it. At the end, swap the pivot into the slot just past the zone. That slot is the pivot's final index, which the function returns so quick sort knows where to split.

#include <iostream>
#include <vector>
#include <utility>   // std::swap

// Lomuto partition: pivot = last element. Returns pivot's final index.
int partition(std::vector<int>& arr, int low, int high) {
    int pivot = arr[high];
    int i = low - 1;                       // boundary of the "smaller" zone
    for (int j = low; j < high; ++j) {
        if (arr[j] < pivot) {
            ++i;
            std::swap(arr[i], arr[j]);     // move a small value into the zone
        }
    }
    std::swap(arr[i + 1], arr[high]);      // drop pivot just past the zone
    return i + 1;
}

int main() {
    std::vector<int> arr = {7, 2, 9, 4, 3, 6};
    int p = partition(arr, 0, (int)arr.size() - 1);

    std::cout << "pivot landed at index " << p << "\n";
    std::cout << "array now: ";
    for (int v : arr) std::cout << v << ' ';
    std::cout << std::endl;          // e.g. 2 4 3 6 7 9, pivot 6 at index 3
    return 0;
}

Now recurse on the two sides and you have the full quick sort.

#include <iostream>
#include <vector>
#include <utility>

int partition(std::vector<int>& arr, int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; ++j) {
        if (arr[j] < pivot) {
            ++i;
            std::swap(arr[i], arr[j]);
        }
    }
    std::swap(arr[i + 1], arr[high]);
    return i + 1;
}

void quickSort(std::vector<int>& arr, int low, int high) {
    if (low >= high) return;                 // base case: 0 or 1 element
    int p = partition(arr, low, high);
    quickSort(arr, low, p - 1);              // sort the smaller side
    quickSort(arr, p + 1, high);             // sort the larger side
}

int main() {
    std::vector<int> data = {38, 27, 43, 3, 9, 82, 10};
    quickSort(data, 0, (int)data.size() - 1);

    std::cout << "sorted: ";
    for (int v : data) std::cout << v << ' ';
    std::cout << std::endl;          // sorted: 3 9 10 27 38 43 82
    return 0;
}

Build it

Save the listing as quicksort.cpp, then compile and run:

g++ -std=c++17 quicksort.cpp -o quicksort && ./quicksort

When the pivot splits the list roughly in half each time, quick sort has log n layers of n work, so it averages O(n log n) and sorts in place with no extra array. The trap is a bad pivot: on an already-sorted list, taking the last element peels off just one value per pass, giving n layers and a O(n²) worst case. Picking a random or middle pivot dodges that in practice.

Q1. Describe the steps of merge sort and state its time complexity. Explain why it has that complexity.

Model answer

Merge sort is a divide-and-conquer sort. The steps:

  1. If the list has 0 or 1 elements it is already sorted, so return it (the base case).
  2. Split the list into a left half and a right half at the middle.
  3. Merge sort the left half and merge sort the right half, recursively. Each half keeps splitting until every piece is a single element.
  4. Merge the two sorted halves into one sorted list by comparing their front elements and copying the smaller each time.

Its time complexity is O(n log n) in the best, average, and worst case. The reason: halving the list repeatedly makes about log₂(n) levels of splitting, and at each level the merges together touch all n elements exactly once. So the work is n per level times log n levels, giving n log n. It also uses O(n) extra memory for the merged output.

Q2. Write a C++ function that merges two already-sorted arrays (or vectors) into a single sorted array. State the reasoning behind the algorithm.

Model answer

Because both inputs are already sorted, the smallest value not yet used is always at the front of one of the two lists. So keep one index on each list, compare the two fronted values, copy the smaller to the output, and advance that index. When one list empties, copy the rest of the other.

#include <iostream>
#include <vector>

std::vector<int> merge(const std::vector<int>& a, const std::vector<int>& b) {
    std::vector<int> out;
    size_t i = 0, j = 0;
    while (i < a.size() && j < b.size()) {
        if (a[i] <= b[j]) out.push_back(a[i++]);
        else              out.push_back(b[j++]);
    }
    while (i < a.size()) out.push_back(a[i++]);
    while (j < b.size()) out.push_back(b[j++]);
    return out;
}

int main() {
    std::vector<int> a = {1, 4, 7};
    std::vector<int> b = {2, 3, 8, 9};
    for (int v : merge(a, b)) std::cout << v << ' ';   // 1 2 3 4 7 8 9
    std::cout << std::endl;
    return 0;
}

The merge does one pass over both lists, so it runs in O(n + m) time for inputs of sizes n and m.

Q3. Describe the steps of quick sort, and explain what the pivot is and why the choice of pivot matters.

Model answer

Quick sort is divide-and-conquer done in place. The steps:

  1. If the section has 0 or 1 elements, stop (base case).
  2. Choose one element as the pivot.
  3. Partition: rearrange the section so all values smaller than the pivot are to its left and all larger are to its right. The pivot is now in its final sorted position.
  4. Recursively quick sort the left part and the right part. No merge step is needed.

The pivot is the reference value that one partition pass compares every other element against: smaller goes left, larger goes right. After the pass, the pivot sits exactly where it belongs in the final order.

The choice matters because it decides how evenly the section splits. A pivot near the median splits it roughly in half, giving about log n levels and an average of O(n log n). A pivot that is the smallest or largest value leaves one side almost empty; if that happens every time (for example, always taking the last element of an already-sorted list), there are n levels and the sort degrades to O(n²). Choosing a random or middle element avoids that worst case in practice.

Q4. Write the partition function used by quick sort (Lomuto scheme, pivot = last element) and explain what value it returns.

Model answer

#include <utility>   // std::swap
#include <vector>

int partition(std::vector<int>& arr, int low, int high) {
    int pivot = arr[high];         // pivot is the last element
    int i = low - 1;               // last index of the "smaller than pivot" zone
    for (int j = low; j < high; ++j) {
        if (arr[j] < pivot) {
            ++i;
            std::swap(arr[i], arr[j]);
        }
    }
    std::swap(arr[i + 1], arr[high]);   // put the pivot just past the zone
    return i + 1;                       // the pivot's final index
}

It returns the index where the pivot ends up after the rearrangement. That index is the pivot's final sorted position, so quick sort recurses on [low, index - 1] and [index + 1, high], never touching the pivot again.

Q5. Both merge sort and quick sort average O(n log n). Give one clear difference between them in extra memory used and in worst-case time.

Model answer

Extra memory: merge sort needs O(n) extra space, because each merge builds a new list to hold the combined result. Quick sort sorts in place by swapping within the same array, so it needs only O(log n) extra space for the recursion, no second array.

Worst-case time: merge sort stays O(n log n) even in the worst case, because it always splits exactly in half regardless of the values. Quick sort's worst case is O(n²), which happens when the pivot is repeatedly the smallest or largest value (for example, taking the last element of an already-sorted list) so one side of each partition is empty.
