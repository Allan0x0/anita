Chapter 20

Trees

Stand under a finished roof truss and look up. One peak, the king-post, sits at the top. From it, two rafters fall away to the left and right, and each rafter can carry smaller struts under it. Nothing loops back on itself: you never climb a rafter and end up back at the peak. That shape, one thing at the top and everything branching downward without loops, is a tree. Learn to see it in a truss and you already understand the data structure that databases, file systems, and menu screens are built from.

A tree is a set of nodes joined by edges, with one node at the top called the root and no loops anywhere. Every node except the root has exactly one node above it (its parent), and may have nodes below it (its children).

A binary tree is the common case: each node has at most two children, a left child and a right child. That is the whole rule. The king-post truss is a binary tree drawn in timber: the peak is the root, and it branches into a left side and a right side.

Key words, all from the truss picture:

  • Root: the top node, the one with no parent. The king-post peak.
  • Leaf: a node with no children. The feet of the truss, where the rafters land on the wall.
  • Subtree: any node together with everything hanging below it. The whole left half of the truss is a subtree; so is the right half.
  • Height: the longest run of edges from the root down to a leaf. A lone root has height 0; a truss two joints deep has height 2. A short bushy tree searches fast; a tall lopsided one does not.

A plain binary tree lets you store two children per node, but it does not say where a new value goes. A binary search tree (BST) adds one rule that makes it useful: for every node, everything in its left subtree is smaller, and everything in its right subtree is larger.

The BST insert rule. To add a value, start at the root and walk down: if the new value is less than the node, go left; if greater, go right; repeat until you reach an empty spot, and plant the value there. The first value you ever insert becomes the root.

Walk the numbers 50, 30, 70, 20, 40, 60, 80 through that rule and you get the tree below. 50 lands first, so it is the root. 30 is less than 50, so it goes left; 70 is greater, so it goes right; and so on down.

In C++ a node is a small struct holding a value and two pointers. An empty branch is a null pointer. Here is the whole thing: build the tree from the numbers above, then read it back in order.

#include <iostream>

struct Node {
    int value;
    Node* left;
    Node* right;
};

// Make a fresh leaf node.
Node* makeNode(int value) {
    Node* n = new Node;
    n->value = value;
    n->left = nullptr;
    n->right = nullptr;
    return n;
}

// BST insert: smaller goes left, larger goes right.
Node* insert(Node* root, int value) {
    if (root == nullptr) return makeNode(value);
    if (value < root->value)      root->left  = insert(root->left, value);
    else if (value > root->value) root->right = insert(root->right, value);
    return root; // duplicates are ignored
}

// In-order traversal: left subtree, then this node, then right subtree.
void inOrder(Node* root) {
    if (root == nullptr) return;
    inOrder(root->left);
    std::cout << root->value << ' ';
    inOrder(root->right);
}

int main() {
    Node* root = nullptr;
    int nums[] = {50, 30, 70, 20, 40, 60, 80};
    for (int n : nums) root = insert(root, n);

    std::cout << "in-order: ";
    inOrder(root);
    std::cout << std::endl;
    return 0;
}

Build it

Save the listing as bst.cpp, then compile and run:

g++ -std=c++17 bst.cpp -o bst && ./bst

On the truss, this is the moment you nail the king-post at the apex first, then hang each rafter and strut off the joint above it, working down to the feet. Insert the peak (the first value) before anything else, exactly as the code sets root from the first number, then let every later piece find its own place by the left-smaller, right-larger rule.

Three ways to read a tree. A traversal visits every node once. Which order you print the node in, relative to its two subtrees, changes the result:

  • In-order: left, node, right. For a BST this prints the values sorted. From the tree above: 20 30 40 50 60 70 80.
  • Pre-order: node, left, right. Prints the root first, handy for copying a tree. Above: 50 30 20 40 70 60 80.
  • Post-order: left, right, node. Prints children before parents, handy for freeing a tree. Above: 20 40 30 60 80 70 50.

Same tree, three orders, one tiny change in where the print line sits.

#include <iostream>

struct Node {
    int value;
    Node* left;
    Node* right;
};

Node* makeNode(int value) {
    Node* n = new Node;
    n->value = value;
    n->left = nullptr;
    n->right = nullptr;
    return n;
}

Node* insert(Node* root, int value) {
    if (root == nullptr) return makeNode(value);
    if (value < root->value)      root->left  = insert(root->left, value);
    else if (value > root->value) root->right = insert(root->right, value);
    return root;
}

void preOrder(Node* r)  { if (!r) return; std::cout << r->value << ' '; preOrder(r->left);  preOrder(r->right); }
void inOrder(Node* r)   { if (!r) return; inOrder(r->left);  std::cout << r->value << ' '; inOrder(r->right); }
void postOrder(Node* r) { if (!r) return; postOrder(r->left); postOrder(r->right); std::cout << r->value << ' '; }

int main() {
    Node* root = nullptr;
    int nums[] = {50, 30, 70, 20, 40, 60, 80};
    for (int n : nums) root = insert(root, n);

    std::cout << "pre-order:  "; preOrder(root);  std::cout << '\n';
    std::cout << "in-order:   "; inOrder(root);   std::cout << '\n';
    std::cout << "post-order: "; postOrder(root); std::cout << '\n';
    return 0;
}

Tree versus graph. A tree is a special, tidy kind of graph. A graph is just nodes joined by edges, with no rules: edges can loop, a node can have many things pointing at it, and there may be no single starting point. A tree adds three restrictions: one root, exactly one parent per node, and no cycles (you can never walk a path that returns to where you started).

Think of tourist spots. A tree is the day plan handed out at the hotel: start at the hotel (root), then the falls or the market, and each of those leads to its own smaller stops, always downward, never back. A graph is the real road map: the falls, the market, and the museum are all linked to each other, roads loop, and you can drive from any one to any other. Same towns, but the map has cycles and the day plan does not.

Q1. Define a binary search tree and state the rule used to insert a new value into it.

Model answer

A binary search tree is a binary tree (each node has at most two children, a left and a right) in which, for every node, all values in its left subtree are smaller than the node and all values in its right subtree are larger.

The insert rule: begin at the root. Compare the new value with the current node. If it is smaller, move to the left child; if it is larger, move to the right child. Repeat until you reach an empty (null) position, and place the new value there as a new leaf. The first value inserted into an empty tree becomes the root. (Equal values are usually ignored, so the tree holds no duplicates.)

Q3. Using a tree of your choice as an example, define each of these terms: root, leaf, subtree, and height.

Model answer

Take the tree from Q2 (root 55).

  • Root: the single top node with no parent. Here, 55.
  • Leaf: a node with no children. Here, 20, 45, and 70.
  • Subtree: a node together with all nodes below it. For example, node 30 with its children 20 and 45 forms the left subtree of the root.
  • Height: the number of edges on the longest path from the root down to a leaf. Here it is 2 (for example 55 to 30 to 20, two edges). A single lone node has height 0.

Q4. Explain the difference between a tree and a graph.

Model answer

Both are made of nodes joined by edges, but a tree is a restricted kind of graph. A general graph has no rules: edges may form cycles (a path that returns to its start), a node may be reached by many edges, and there need not be any single starting node.

A tree adds three conditions: it has exactly one root, every node except the root has exactly one parent, and there are no cycles. So a tree is a connected graph with no loops and a chosen top node. In short, every tree is a graph, but not every graph is a tree. A tourist day plan (start at the hotel, branch out, never loop back) is a tree; the full road map linking every spot to every other, with loops, is a graph.

Q5. Write a complete C++ program that inserts a list of integers into a binary search tree and prints them in sorted order using an in-order traversal.

Model answer

The in-order traversal of a BST is exactly a sort, so no separate sorting step is needed. Build the tree, then walk it left-node-right.

#include <iostream>

struct Node {
    int value;
    Node* left;
    Node* right;
};

Node* insert(Node* root, int value) {
    if (root == nullptr) {
        Node* n = new Node;
        n->value = value;
        n->left = nullptr;
        n->right = nullptr;
        return n;
    }
    if (value < root->value)      root->left  = insert(root->left, value);
    else if (value > root->value) root->right = insert(root->right, value);
    return root;
}

void inOrder(Node* root) {
    if (root == nullptr) return;
    inOrder(root->left);
    std::cout << root->value << ' ';
    inOrder(root->right);
}

int main() {
    Node* root = nullptr;
    int data[] = {40, 20, 60, 10, 30, 50, 70};
    for (int v : data) root = insert(root, v);

    std::cout << "sorted: ";
    inOrder(root);          // prints 10 20 30 40 50 60 70
    std::cout << std::endl;
    return 0;
}

The program prints sorted: 10 20 30 40 50 60 70. The insert function places each value by the left-smaller, right-larger rule, and the in-order walk reads the whole tree back in ascending order.
