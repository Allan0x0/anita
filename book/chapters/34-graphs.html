Chapter 34

Graphs

Unfold a tourist map of a town and look at what it really is: dots for the places worth seeing (the falls, the market, the museum) and lines for the roads that join them. Some roads run both ways; a few are one way only. There is no top and no bottom, no single starting point, and you can drive in a circle and end up where you began. That picture, dots joined by lines with no rules about loops or direction, is a graph. Trees were the tidy special case; graphs are the whole messy world, and they model road maps, friend lists, web links, and the trusses whose joints brace each other.

A graph is a set of vertices (also called nodes, the dots) joined by edges (the lines). That is the entire definition. Unlike a tree, a graph has no root, a vertex can be joined to any number of others, and edges may form cycles (a path that returns to where it started).

The one big fork is direction.

  • Undirected graph: an edge between A and B works both ways. If you can walk from the market to the falls, you can walk back. A two-way road, or a friendship (if you are my friend, I am yours).
  • Directed graph (digraph): each edge has a direction, an arrow from one vertex to another. A to B does not imply B to A. A one-way street, or "follows" on a social app: you can follow a page that does not follow you back.

How you store a graph in code. Two representations cover almost everything:

  • Adjacency list: for each vertex, keep a list of the vertices it joins. In C++ that is a std::vector of std::vector<int>: adj[2] holds every stop reachable in one hop from stop 2. Compact when the map is sparse (few roads per town), which real maps are.
  • Adjacency matrix: a grid of booleans where m[i][j] is true when an edge joins i to j. Simple, but it spends space on every pair whether or not a road exists, so it wastes room on sparse maps.

For an undirected graph you record each edge twice (2 in the list of 5, and 5 in the list of 2); for a directed graph you record it only in the direction the arrow points. This book uses adjacency lists.

Here is the tourist map we will traverse. Six stops, numbered 0 to 5, joined by two-way roads. It is undirected and it has cycles (0, 2, 3, 1 and back to 0 is a loop), so it is a graph and not a tree.

Breadth-First Search (BFS) explores in rings. Start at one vertex, visit all of its direct neighbours, then all of their unvisited neighbours, and so on, spreading outward one hop at a time like a ripple. It uses a queue (first in, first out): you push a vertex when you first see it, and process vertices in the order they arrived. Because it fans out in rings, BFS on an unweighted graph finds the path with the fewest hops from the start to every other vertex.

Run BFS from stop 0 on the map above. Visit 0, then its neighbours 1 and 2, then their new neighbours 3 and 4, then 5. The visit order comes out 0 1 2 3 4 5.

#include <iostream>
#include <vector>
#include <queue>

int main() {
    // Six tourist stops, 0..5. adj[x] lists the stops joined to x.
    std::vector<std::vector<int>> adj = {
        {1, 2},        // 0 Hotel
        {0, 3},        // 1 Falls
        {0, 3, 4},     // 2 Market
        {1, 2, 5},     // 3 Museum
        {2, 5},        // 4 Bridge
        {3, 4}         // 5 Park
    };

    int start = 0;
    std::vector<bool> seen(adj.size(), false);
    std::queue<int> q;

    seen[start] = true;   // mark when you push, not when you pop
    q.push(start);

    std::cout << "BFS from " << start << ": ";
    while (!q.empty()) {
        int node = q.front();
        q.pop();
        std::cout << node << ' ';
        for (int next : adj[node]) {
            if (!seen[next]) {
                seen[next] = true;
                q.push(next);
            }
        }
    }
    std::cout << std::endl;   // prints: BFS from 0: 0 1 2 3 4 5
    return 0;
}

Build it

Save as bfs.cpp, then compile and run:

g++ -std=c++17 bfs.cpp -o bfs && ./bfs

The seen vector is the whole trick: mark a stop the moment you push it, so the same stop never joins the queue twice. Forget that mark on a graph with cycles and BFS loops forever, driving the same ring road again and again.

Depth-First Search (DFS) does the opposite. Instead of spreading in rings, it plunges: from a vertex it walks to the first unvisited neighbour, then that vertex's first unvisited neighbour, going as deep as it can before it runs out of new stops and backs up to try the next branch. It is the natural fit for recursion, where the call stack does the remembering, or a plain stack (last in, first out) if you write it by hand.

Run DFS from stop 0. Go 0, then dive to 1, from 1 dive to 3, from 3 dive to 2, from 2 dive to 4, from 4 reach 5. Every later branch is already visited, so it unwinds. The visit order is 0 1 3 2 4 5, different from BFS on the same map.

#include <iostream>
#include <vector>

std::vector<std::vector<int>> adj = {
    {1, 2}, {0, 3}, {0, 3, 4}, {1, 2, 5}, {2, 5}, {3, 4}
};
std::vector<bool> seen(6, false);

// Visit this stop, then dive into each unvisited neighbour in turn.
void dfs(int node) {
    seen[node] = true;
    std::cout << node << ' ';
    for (int next : adj[node]) {
        if (!seen[next]) dfs(next);
    }
}

int main() {
    std::cout << "DFS from 0: ";
    dfs(0);
    std::cout << std::endl;   // prints: DFS from 0: 0 1 3 2 4 5
    return 0;
}

Build it

Save as dfs.cpp, then compile and run:

g++ -std=c++17 dfs.cpp -o dfs && ./dfs

Same map, same start, same seen guard against cycles. The only change from BFS is the container in your head: a queue fans out in rings, the recursion stack plunges down one branch first.

Spanning tree. Take a connected graph and pick just enough edges to keep every vertex joined, with no cycles left. The result is a tree that "spans" (touches) all the vertices, called a spanning tree. For a graph with n vertices a spanning tree always has exactly n minus 1 edges: fewer and something falls off the network, more and you have made a cycle. On the road map it is the smallest set of roads that still lets a tour bus reach every stop.

Minimum spanning tree (MST). Now put a weight on each edge: the length of the road in kilometres, or the cost to pave it. Many spanning trees exist; the minimum spanning tree is the one whose edge weights add to the smallest total. Same job (reach every stop, no cycles) at the lowest cost. It is exactly what you want when laying water pipe or fibre to every town for the least trench dug.

Q1. Define a graph. Explain the difference between a directed and an undirected graph, giving one real-world example of each.

Model answer

A graph is a set of vertices (nodes) joined by edges (links). Unlike a tree it has no root, a vertex may join any number of others, and its edges may form cycles (paths that return to their start).

In an undirected graph an edge has no direction: an edge between A and B means you can travel from A to B and from B to A. Example: a network of two-way roads between towns, or a friendship list where being friends is mutual.

In a directed graph (digraph) each edge is an arrow with a direction: an edge from A to B lets you go A to B but not necessarily B to A. Example: a system of one-way streets, or "follows" on a social app, where you can follow an account that does not follow you back.

Q2. Explain how Breadth-First Search (BFS) traverses a graph, and state which data structure it uses. Using the graph with edges 0-1, 0-2, 1-3, 2-3, 2-4, 3-5, 4-5, give the order BFS visits the vertices starting from vertex 0.

Model answer

BFS explores the graph in rings. Starting from one vertex it first visits all of that vertex's direct neighbours, then all of their unvisited neighbours, and so on, spreading outward one hop at a time. It uses a queue (first in, first out): each vertex is pushed when it is first discovered and marked as visited at that moment, so it is never queued twice. This matters on graphs with cycles, where an unmarked vertex would be visited forever.

Starting from vertex 0: visit 0 and push its neighbours 1 and 2; visit 1 and push its new neighbour 3; visit 2 and push its new neighbour 4; visit 3 and push 5; visit 4 (5 already queued); visit 5. The visit order is:

0, 1, 2, 3, 4, 5.

Because BFS fans out ring by ring, this order also gives the fewest-hop distance from vertex 0 to every other vertex.

Q3. Explain how Depth-First Search (DFS) differs from BFS, and state which data structure it uses. Draw or describe the DFS visit order for the same graph starting from vertex 0.

Model answer

DFS goes deep instead of wide. From the start vertex it walks to the first unvisited neighbour, then to that vertex's first unvisited neighbour, diving as far as it can along one branch before backing up to try the next. Where BFS uses a queue, DFS uses a stack (last in, first out); most often this is the call stack of a recursive function, so no explicit stack is written.

On the same graph from vertex 0: go to 0, dive to 1, from 1 dive to 3, from 3 dive to 2, from 2 dive to 4, from 4 reach 5. Every remaining edge leads to an already-visited vertex, so the search unwinds. The visit order is:

0, 1, 3, 2, 4, 5.

Q4. Define a spanning tree and a minimum spanning tree (MST). For a connected graph of n vertices, how many edges does any spanning tree have?

Model answer

A spanning tree of a connected graph is a subset of its edges that keeps every vertex connected while containing no cycle. It is a tree (connected, no loops) that touches, or spans, all the vertices. For a graph of n vertices, any spanning tree has exactly n minus 1 edges: with fewer, the graph would split into pieces; with more, some edge would close a cycle.

A minimum spanning tree is a spanning tree of a weighted graph (each edge carries a weight, such as distance or cost) whose edge weights add up to the smallest possible total. A graph can have many spanning trees; the MST is the cheapest one. For example, to lay water pipe to every town for the least total trench, you build the MST of the road graph. In the weighted five-vertex example, choosing edges A-C (3), B-C (2), C-E (4) and E-D (1) spans all five vertices with 4 edges for a total weight of 10, less than any other choice.

Q5. Write a complete C++ program that stores an undirected graph as an adjacency list and prints the vertices reachable from a start vertex using a breadth-first traversal.

Model answer

Store the graph as a std::vector of neighbour lists, then run BFS with a queue, marking each vertex when it is pushed so cycles cannot cause an endless loop.

#include <iostream>
#include <vector>
#include <queue>

int main() {
    // Undirected graph: each edge is listed at both of its ends.
    std::vector<std::vector<int>> adj = {
        {1, 2},        // 0
        {0, 3},        // 1
        {0, 3, 4},     // 2
        {1, 2, 5},     // 3
        {2, 5},        // 4
        {3, 4}         // 5
    };

    int start = 0;
    std::vector<bool> seen(adj.size(), false);
    std::queue<int> q;
    seen[start] = true;
    q.push(start);

    std::cout << "reachable from " << start << ": ";
    while (!q.empty()) {
        int node = q.front();
        q.pop();
        std::cout << node << ' ';
        for (int next : adj[node]) {
            if (!seen[next]) {
                seen[next] = true;
                q.push(next);
            }
        }
    }
    std::cout << std::endl;   // reachable from 0: 0 1 2 3 4 5
    return 0;
}

The program prints reachable from 0: 0 1 2 3 4 5. Every vertex it prints is reachable from the start; any vertex missing from the output would sit in a disconnected part of the graph.
