Chapter 11

Arrays: a whole cut-list in one box

A roof truss is a lot of straight pieces of timber, one after another: top chord, bottom chord, king post, web after web. Write a separate variable for each and you drown in names before the frame is even up. An array is one box with many numbered slots, so the whole cut-list lives under a single name. Store the lengths once, then loop over them to total the timber, find the longest member, or print the order sheet.

What an array is

An array is a fixed run of slots of the same type, laid end to end in memory. You give the whole run one name and a size. Each slot has an index, its position, and the count starts at zero: the first slot is index 0, the last is index size minus one. Reach a slot with square brackets, so cut[0] is the first member and cut[4] is the fifth.

Declare, initialise, traverse

Three moves cover most array work. Declare: name the type, the array name, and the size in brackets. Initialise: fill the slots, often with a brace list { ... } at declaration. Traverse: walk the slots with a for loop whose counter runs from 0 up to size minus one. The cut-list below is declared, initialised, and traversed to total the timber.

#include <iostream>

int main() {
    // declare + initialise: five member lengths in mm
    int cut[5] = {4800, 4800, 1200, 2600, 2600};

    int total = 0;
    // traverse: index 0 through 4
    for (int i = 0; i < 5; i = i + 1) {
        std::cout << "Member " << i << ": " << cut[i] << " mm" << std::endl;
        total = total + cut[i];
    }

    std::cout << "Total timber: " << total << " mm" << std::endl;
    return 0;
}

Build it

Save as cutlist.cpp, then:

g++ -std=c++17 cutlist.cpp -o cutlist && ./cutlist

Truss build step: this is your order sheet. The loop prints one line per member and the last line, Total timber: 16000 mm, is the length of pine to buy for one truss. Multiply by the number of trusses and you have the whole roof's timber in one run.

Largest and smallest in one pass

To find the longest or shortest member you do not need to sort anything. Take the first slot as your current best, then walk the rest; whenever a slot beats the current best, keep it. One pass, one comparison per slot.

#include <iostream>

int main() {
    int cut[5] = {4800, 4800, 1200, 2600, 2600};

    int longest = cut[0];
    int shortest = cut[0];
    for (int i = 1; i < 5; i = i + 1) {
        if (cut[i] > longest)  longest = cut[i];
        if (cut[i] < shortest) shortest = cut[i];
    }

    std::cout << "Longest member: " << longest << " mm" << std::endl;
    std::cout << "Shortest member: " << shortest << " mm" << std::endl;
    return 0;
}

Challenge: spot the bug

A student writes the traversal as for (int i = 0; i <= 5; i = i + 1) over an array of size 5 and the program prints one garbage length, sometimes crashing. What is wrong? (Answer: the valid indices are 0 to 4. The condition i <= 5 lets i reach 5, one past the end, and reads memory the array does not own. Use i < 5. C++ does not check bounds for you, which is exactly why this bug is so easy to write.)

Two dimensions: the truss grid

A single array is a line. A 2-D array is a grid: rows and columns, like a table. Declare it with two sizes in brackets, [rows][cols], and reach a cell with two indices, grid[r][c]. A roof is not one truss but a row of them across the building; think of a grid where each row is one truss and each column is the same member across every truss. Read a whole row to build one truss; read down a column to see how one member repeats.

Row-major order

Memory is a straight line, but a grid is two-dimensional, so C++ has to flatten it. It stores row by row: the whole of row 0, then the whole of row 1, then row 2. This is row-major order. It is why a 2-D loop puts the row on the outside and the column on the inside; that order walks memory in the same line it is laid out, which is the fast way to read it.

#include <iostream>

int main() {
    // 3 trusses, 3 members each
    int grid[3][3] = {
        {4800, 1200, 2600},
        {4800, 1200, 2600},
        {4800, 1200, 2600}
    };

    // row-major traversal: row outside, column inside
    for (int r = 0; r < 3; r = r + 1) {
        std::cout << "Truss " << r << ":";
        for (int c = 0; c < 3; c = c + 1) {
            std::cout << " " << grid[r][c];
        }
        std::cout << std::endl;
    }
    return 0;
}

To total the whole grid, keep the same nested loop but add every cell into one running sum. The roof's entire timber order falls out of one pass.

#include <iostream>

int main() {
    int grid[3][3] = {
        {4800, 1200, 2600},
        {4800, 1200, 2600},
        {4800, 1200, 2600}
    };

    int total = 0;
    for (int r = 0; r < 3; r = r + 1) {
        for (int c = 0; c < 3; c = c + 1) {
            total = total + grid[r][c];
        }
    }

    std::cout << "Whole roof: " << total << " mm of timber" << std::endl;
    return 0;
}

The demerits of arrays

Arrays are fast and simple, but they buy that with hard limits. Know them before you lean on an array.

  • Fixed size. You set the length when you write the code. A five-slot cut-list cannot grow to six at run time; you would declare a new, bigger array and copy across.
  • No bounds checking. C++ does not stop you reading cut[7] in a size-5 array. It reads whatever memory sits there: garbage, or a crash. The mistake is silent.
  • Costly insert and delete. To insert in the middle you must shuffle every later element along by one. For a big array that is a lot of moving.
  • One type only. Every slot holds the same type. You cannot mix a length and a name in the same array.
  • Wasted space. Size for the worst case and the unused slots still cost memory whether you fill them or not.

Later chapters reach for the linked list and the vector precisely to beat the first and third of these: structures that grow and shrink at run time.

The same tool, other jobs

Nothing about arrays is special to timber. Swap the meaning of the slots and the same loops solve other problems. A recipe is an array of ingredient weights; a tour is an array of distances between stops. Below, one pass finds the heaviest ingredient in a bread recipe.

#include <iostream>
#include <string>

int main() {
    std::string name[4] = {"flour", "water", "salt", "yeast"};
    int grams[4] = {500, 320, 10, 7};

    int heaviest = 0;   // index of the biggest so far
    for (int i = 1; i < 4; i = i + 1) {
        if (grams[i] > grams[heaviest]) heaviest = i;
    }

    std::cout << "Most of: " << name[heaviest]
              << " (" << grams[heaviest] << " g)" << std::endl;
    return 0;
}

Exam questions

Q1. Declare and initialise a 2-D array called tour holding the distances (in km) between three towns and three viewpoints, then print it in row-major order. Explain what row-major order means.

Model answer

Declare with two sizes, initialise with nested brace lists, and traverse with the row loop on the outside and the column loop on the inside. That outer-row, inner-column order is row-major: it visits the cells in the exact order C++ stores them in memory, the whole of row 0, then row 1, then row 2.

#include <iostream>

int main() {
    int tour[3][3] = {
        {12, 40, 8},
        {5, 33, 21},
        {18, 9, 27}
    };

    for (int r = 0; r < 3; r = r + 1) {
        for (int c = 0; c < 3; c = c + 1) {
            std::cout << tour[r][c] << " ";
        }
        std::cout << std::endl;
    }
    return 0;
}

Q2. Write a program that finds the largest and smallest value in an array of six member lengths, using a single pass.

Model answer

Seed both the largest and smallest from element 0, then walk from element 1 to the end. Replace largest whenever a value is bigger, replace smallest whenever a value is smaller. One loop does both.

#include <iostream>

int main() {
    int len[6] = {2600, 4800, 1200, 3600, 900, 4800};

    int largest = len[0];
    int smallest = len[0];
    for (int i = 1; i < 6; i = i + 1) {
        if (len[i] > largest)  largest = len[i];
        if (len[i] < smallest) smallest = len[i];
    }

    std::cout << "Largest: " << largest << " mm" << std::endl;
    std::cout << "Smallest: " << smallest << " mm" << std::endl;
    return 0;
}

Q3. Write a program that sums every element of a 2-D array of size 2 by 4 (two shelves, four jars each) and prints the total.

Model answer

A nested loop, row outside and column inside, adds each cell into a running total. After both loops finish, the total holds the sum of all eight cells.

#include <iostream>

int main() {
    int jars[2][4] = {
        {3, 5, 2, 8},
        {6, 1, 4, 7}
    };

    int total = 0;
    for (int r = 0; r < 2; r = r + 1) {
        for (int c = 0; c < 4; c = c + 1) {
            total = total + jars[r][c];
        }
    }

    std::cout << "Total jars: " << total << std::endl;
    return 0;
}

Q4. State four demerits (drawbacks) of arrays as a data structure.

Model answer

Any four of the following, each with a one-line reason:

  • Fixed size: the length is set at compile time and cannot grow at run time.
  • No bounds checking: reading past the end reads invalid memory silently instead of raising an error.
  • Costly insert and delete: making room in the middle means shifting every later element along.
  • Single type: every slot must hold the same type.
  • Wasted space: sizing for the worst case leaves unused slots that still take memory.
