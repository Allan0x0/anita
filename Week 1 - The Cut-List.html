BITH132 · Week 1

The Cut-List

Unit 1: Arrays. An array is a row of boxes that all hold the same kind of value. This week the boxes are your cut-list: one length per truss member. You will fill it, measure it, and teach it to add itself up.

Day 1 · Declare

A row of boxes, counted from zero

An array is many variables in one: a row of boxes, all the same type, under one name. Perfect for a cut-list.

float cut[7]; makes seven boxes. You reach each by its index: cut[0] is the first, cut[6] the last. The count starts at 0, so seven boxes run 0 to 6.

The code

cut[0] is the first box, not cut[1]. Off-by-one bugs live here.

Build it

Compile and run: gcc day1_declare.c -o day1 then ./day1. Then set cut[6] = 1.2; and print it. Try cut[7] and notice it is past the end (0 to 6 only).

Check yourself

Day 2 · Fill

Fill the list, walk it with a loop

You can fill every box at once when you declare the array, then a loop walks all of them.

The loop counter doubles as the index: cut[i] reaches box i. This is the pattern behind almost everything with arrays.

The code

i < 7 stops at 6, the last valid index. That is why we test with <, not <=.

Build it

Run it. Then change a couple of lengths and re-run. Add a line before the loop that prints how many members there are (hint: it is 7 for now).

Check yourself

Day 3 · Measure

Total, longest, shortest

Now the array earns its keep. One walk through the boxes can add them up and track the biggest and smallest at the same time.

Start longest and shortest at the first member, then compare each box against them. This "carry the best so far" trick returns again in sorting and searching.

The code

One loop, three answers. Walking n boxes once is O(n) work: the time grows in step with the number of members.

Build it

Run it. Then also count how many members are longer than 2.0 m (add an int count and an if inside the loop).

Check yourself

Day 4 · Functions

Hand the whole list to a function

You pass an array to a function by giving just its name, no brackets. The function receives the same boxes, so it works on your real cut-list.

Notice the size is passed separately (n): the function cannot tell how long the array is on its own. Keep that in mind; in Unit 4 you learn why (the name is really an address).

The code

#define N 7 names the size once. Change it in one place and the whole program follows.

Build it

Run it. Then write your own function float longest_member(float cut[], int n) and call it from main. Reuse the pattern from Day 3.

Check yourself

Day 5 · Grid

Many trusses: a 2-D array

One roof has many trusses, each with its own members. A 2-D array is a grid: rows and columns. roof[3][4] is 3 trusses down, 4 members across.

Two indices now: roof[t][m] is truss t, member m. A grid needs two loops, one inside the other.

The code

The outer loop picks a truss (a row); the inner loop walks its members (the columns).

Build it

Run it. Then print a grand total for the whole roof (add every roof[t][m]). Add a 4th truss and watch it just work.

Check yourself

Day 6 · Labels

Member names: strings are char arrays

Numbers are not enough; members have names like "TC1". A string is just an array of characters that ends with a hidden \0 marker. That is Unit 2, and you meet it here.

strlen (from string.h) counts the letters. A list of labels is a 2-D char array: rows are words, columns are letters.

The code

members[4][5]: up to 4 characters per label, plus room for the \0. That is why it is 5, not 4.

Build it

Run it. Then combine the week: print each member with its label AND its length from the cut-list (labels in one array, lengths in another, same index).

Check yourself
