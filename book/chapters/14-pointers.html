Chapter 14

Pointers: a nail from one joint to the next

Picture a roof truss. Each joint is a box holding a value. A pointer is the nail driven from one joint into the next: it does not hold the value itself, it holds where the next value lives. Learn to read that nail and you can walk a whole frame, change a joint from across the room, and hand one big timber to a helper without carrying a copy of it. That is what pointers buy you, and every list, tree, and graph later in this book is built from them.

Every variable lives at an address in memory, a number like a plot number on a street. A pointer is a variable whose value is that address. Two operators do the whole job. The address-of operator & asks "where does this live?" and hands you the address. The dereference operator * asks "what is at this address?" and hands you the value back. You write the pointer's type with a *: int* p means "p points at an int".

#include <iostream>

int main() {
    int span = 48;          // an int joint, value 48
    int* p = &span;        // p is a nail into span
    std::cout << "value of span:   " << span  << std::endl;
    std::cout << "address of span: " << p     << std::endl;  // the address
    std::cout << "value via *p:    " << *p    << std::endl;  // reach across: 48

    *p = 60;                // change span from across the room
    std::cout << "span is now:     " << span  << std::endl;  // 60
    return 0;
}

Read the two operators as opposites. &span turns a value into its address. *p turns an address back into the value. The line *p = 60; does not change the pointer; it follows the nail and rewrites the joint at the far end. That is the superpower: one pointer lets code edit a value it does not own.

Pointer to a struct: the arrow operator

A joint usually holds more than one number. Group them in a struct. When you hold a pointer to a struct, you could write (*t).span, dereference then pick the field, but that is ugly. C++ gives you the arrow -> as shorthand: t->span means exactly (*t).span. Dot for a value in hand, arrow for a pointer to it.

#include <iostream>
#include <string>

struct Truss {
    std::string name;
    int span;        // millimetres
    int members;     // count of timbers
};

int main() {
    Truss t{ "gable", 4800, 5 };
    Truss* tp = &t;                 // a nail into the truss

    // reach a field through the pointer with ->
    std::cout << tp->name << " spans " << tp->span << "mm" << std::endl;

    tp->span = 5200;                // edit the field through the pointer
    tp->members += 1;
    std::cout << t.name << " now spans " << t.span
              << "mm with " << t.members << " members" << std::endl;
    return 0;
}

Build it

Save the truss program as truss.cpp and run it:

g++ -std=c++17 truss.cpp -o truss && ./truss

Build step, plain: you cut the gable joint at 4800mm, then you widen the span to 5200mm and add one timber, all through the nail tp without touching t by name. The change lands on the real truss because the nail points at it.

Pass by pointer versus pass by reference

By default a function gets a copy of what you pass, so edits inside it vanish when it returns. To let a function change the caller's value, hand it a way back to the original. Two ways.

Pass by pointer. The parameter is a pointer; the caller passes an address with &; the function reaches the value with * or a field with ->. A pointer can be nullptr (pointing at nothing), so the function may have to check first.

Pass by reference. The parameter is written int&; it is an alias for the caller's variable, no address juggling. The caller passes the plain variable, the function uses the plain name. A reference cannot be null and cannot be re-seated, so it is the tidier default when you always have a real value.

#include <iostream>

// pass by pointer: caller sends an address, we follow the nail
void widenByPointer(int* span) {
    if (span == nullptr) return;   // a pointer might point at nothing
    *span += 200;
}

// pass by reference: parameter is an alias for the caller's variable
void widenByReference(int& span) {
    span += 200;                    // no * needed, it is the real thing
}

int main() {
    int a = 4800;
    int b = 4800;
    widenByPointer(&a);            // pass the address of a
    widenByReference(b);           // pass b itself
    std::cout << "a = " << a << ", b = " << b << std::endl;  // 5000, 5000
    return 0;
}

new and delete: joints you make while the roof is going up

So far every value was a joint named at compile time. Sometimes you do not know how many joints you need until the job is running: a recipe with an unknown ingredient count, a tour with a variable number of stops. new asks the system for a fresh box on the heap (the big yard of memory that outlives the current function) and hands back a pointer to it. delete gives that box back. Every new needs exactly one delete, or the box is lost for the rest of the run (a memory leak). Use new[] with delete[] for arrays.

#include <iostream>
#include <string>

struct Recipe {
    std::string dish;
    int servings;
};

int main() {
    // one Recipe on the heap, reached through a pointer
    Recipe* r = new Recipe{ "jollof rice", 4 };
    r->servings = 8;                       // scale it up through ->
    std::cout << r->dish << " for " << r->servings << std::endl;
    delete r;                              // give the single box back

    // an array of ingredient counts, size chosen at run time
    int stops = 3;                         // tourist spots on today's tour
    int* visitors = new int[stops];
    for (int i = 0; i < stops; ++i) visitors[i] = (i + 1) * 100;
    std::cout << "spot 2 had " << visitors[1] << " visitors" << std::endl;
    delete[] visitors;                     // array box: delete[] , not delete
    return 0;
}

Challenge: spot the bug

These lines are meant to double the servings of a recipe on the heap and print it (assume struct Recipe { std::string dish; int servings; }; is defined above). The snippet has two bugs. Find both.

Recipe* r = new Recipe{ "egusi soup", 6 };
r.servings = r.servings * 2;               // (1)
std::cout << r->dish << ": " << r->servings << std::endl;
// (2) ... nothing more before the program ends

Answer. Bug (1): r is a pointer, so a field needs the arrow, r->servings, not the dot r.servings; the dot only works on a value in hand. Bug (2): the new is never matched by a delete r; before return, so the heap box leaks. Fixed, line (1) reads r->servings = r->servings * 2; and a delete r; goes at line (2).

Exam questions

Q1. Explain what a pointer is and why a program would use one. Include the role of the & and * operators.

Model answer

A pointer is a variable that stores the memory address of another variable, rather than a value of its own. Think of it as a nail from one joint to the next: it records where the next value lives. The address-of operator & produces the address of a variable, so int* p = &span; makes p point at span. The dereference operator * does the reverse: *p reads (or with assignment, writes) the value at the stored address, so *p = 60; changes span itself. Programs use pointers to let one piece of code read and change a value it does not own, to pass large objects to functions without copying them, and to build structures whose size is not known until the program runs, such as linked lists and trees.

Q2. Given struct Spot { std::string name; int visitors; }; and a pointer Spot* s that points at a valid Spot, write the statement that adds 50 to that spot's visitors field through the pointer. Explain why the operator you chose is correct.

Model answer

The statement is:

s->visitors = s->visitors + 50;   // or: s->visitors += 50;

Because s is a pointer, not a Spot value, you reach a field with the arrow operator ->. The arrow is shorthand for dereference-then-select: s->visitors means exactly (*s).visitors. Writing s.visitors would be a compile error, since the dot operator only applies to a value in hand, not to a pointer.

Q3. Compare passing a variable to a function by pointer with passing it by reference. Give one advantage of each, and show the function signature for each in a short example that adds one visitor to a spot's count.

Model answer

Both let a function change the caller's variable instead of a copy. The difference is how.

By pointer, the parameter is a pointer, the caller passes an address with &, and the function reaches the value with *. Advantage: a pointer can be nullptr, so it can represent "no value" and be re-pointed at different variables, which is what linked structures need.

By reference, the parameter is an alias (int&) for the caller's variable, so the caller passes the plain variable and the function uses the plain name. Advantage: it cannot be null and needs no &/* juggling, so it is safer and cleaner when a real value always exists.

void addOneByPointer(int* v)   { if (v) *v += 1; }   // caller: addOneByPointer(&count);
void addOneByReference(int& v) { v += 1; }           // caller: addOneByReference(count);

Q4. Explain what new and delete do, and state the rule that ties them together. What goes wrong if that rule is broken? Show a correct pair for a single heap-allocated int and for an array of ints.

Model answer

new allocates a fresh block of memory on the heap (memory that outlives the current function) and returns a pointer to it. delete releases a block that new allocated, giving it back to the system. The rule: every new must be matched by exactly one delete, and every new[] by exactly one delete[]. Break it by forgetting the delete and the block is never reclaimed for the rest of the run, a memory leak; call delete twice on the same block, or use delete on an array made with new[], and the behaviour is undefined (a likely crash). Correct pairs:

int* one = new int(5);        // single int on the heap
delete one;                    // matched with delete

int* many = new int[3];        // array of 3 ints
delete[] many;                 // matched with delete[]
