Chapter 36

Heaps

A busy kitchen has one rule at the pass: the most urgent order goes out next, never mind when it was written. A ticket for a table that has waited an hour jumps ahead of one that just came in. You do not sort every ticket on the rail each time; you just keep the top one always the most urgent, and you can add a new ticket or pull the top one fast. That is exactly what a heap does: it keeps the biggest (or smallest) item ready to grab, without paying to fully sort the rest.

A binary heap is a binary tree with two rules, and only two:

  • Shape (complete tree): every level is full except possibly the last, and the last level fills from the left with no gaps. So the tree is always short and bushy, never a lopsided string.
  • Heap order: in a max-heap, every parent is greater than or equal to its children, so the largest value sits at the root. In a min-heap, every parent is less than or equal to its children, so the smallest sits at the root.

Note what a heap does not promise: left is not smaller than right, and an in-order walk is not sorted. The only guarantee is parent-versus-child. That weaker promise is the whole point; it is cheap to keep, and it is all you need to always know the top value.

The trick that makes heaps cheap: store the tree in an array. Because a heap is always a complete tree, you can lay its nodes out level by level, left to right, in a plain array and skip pointers entirely. Read the same heap top to bottom, left to right, and you get the array below.

Insert (sift up). Adding a value must keep both rules. Keep the shape first: drop the new value into the next free array slot, which is the first empty spot on the last level. That may break heap order, so fix it by sifting up: compare the new value with its parent, and if it is bigger (in a max-heap), swap them; repeat until the parent is bigger or you reach the root. The value climbs only along one path from a leaf to the root, so at most the height of the tree, about log n swaps.

Delete the top (sift down). You almost always remove the root, since that is the max (or min) you came for. Save the root to return it, move the last array element into the root slot (that keeps the tree complete), then sift down: compare the new root with its two children, swap it with the larger child if that child is bigger, and repeat down the tree until both children are smaller or you hit the bottom. Again one path, about log n swaps.

#include <iostream>
#include <vector>

// A max-heap stored in a vector.
// parent(i) = (i-1)/2, left(i) = 2i+1, right(i) = 2i+2.
class MaxHeap {
    std::vector<int> a;

    // Float a[i] up until its parent is not smaller.
    void siftUp(int i) {
        while (i > 0) {
            int parent = (i - 1) / 2;
            if (a[i] <= a[parent]) break;   // heap order already holds
            std::swap(a[i], a[parent]);
            i = parent;
        }
    }

    // Push a[i] down until both children are not larger.
    void siftDown(int i) {
        int n = static_cast<int>(a.size());
        while (true) {
            int left = 2 * i + 1;
            int right = 2 * i + 2;
            int largest = i;
            if (left < n  && a[left]  > a[largest]) largest = left;
            if (right < n && a[right] > a[largest]) largest = right;
            if (largest == i) break;        // no child is larger, done
            std::swap(a[i], a[largest]);
            i = largest;
        }
    }

public:
    void insert(int value) {
        a.push_back(value);                 // fill the next free slot
        siftUp(static_cast<int>(a.size()) - 1);
    }

    int extractMax() {
        int top = a[0];                     // the value we came for
        a[0] = a.back();                    // last element moves to the root
        a.pop_back();
        if (!a.empty()) siftDown(0);
        return top;
    }

    bool empty() const { return a.empty(); }
};

int main() {
    MaxHeap h;
    int nums[] = {20, 15, 30, 40, 10, 25};
    for (int n : nums) h.insert(n);

    std::cout << "largest first: ";
    while (!h.empty()) std::cout << h.extractMax() << ' ';
    std::cout << std::endl;
    return 0;
}

Build it

Save it as heap.cpp, then compile and run:

g++ -std=c++17 heap.cpp -o heap && ./heap

It prints largest first: 40 30 25 20 15 10. Pulling the max over and over drains the heap in sorted order; that is heapsort hiding inside a to-do list that always hands you the biggest job next.

You rarely write this by hand. The standard library ships a heap as std::priority_queue, a max-heap by default. Same result, three lines of logic:

#include <iostream>
#include <queue>

int main() {
    std::priority_queue<int> pq;             // a max-heap, built in
    for (int n : {20, 15, 30, 40, 10, 25}) pq.push(n);

    std::cout << "largest first: ";
    while (!pq.empty()) {
        std::cout << pq.top() << ' ';         // top() is always the max
        pq.pop();
    }
    std::cout << std::endl;
    return 0;
}

Heap versus BST. Both are binary trees, but they answer different questions. A binary search tree (Chapter 20) keeps a full left-right order, so it is fast at "is 42 in here?" and can print everything sorted with an in-order walk. A heap keeps only parent-versus-child order, so it is bad at searching for a middle value (you may have to look almost everywhere) but unbeatable at "what is the biggest right now?", which is O(1) at the root. Use a BST when you search and range-scan; use a heap when you repeatedly want the extreme item, like the kitchen pass always sending out the most urgent ticket.

Challenge (spot the bug)

A student rewrites siftDown like this. It is deliberately broken; do not compile it. What goes wrong, and on which node?

void siftDown(int i) {
    int n = a.size();
    while (true) {
        int left = 2 * i + 1;
        int right = 2 * i + 2;
        int largest = i;
        if (a[left]  > a[largest]) largest = left;    // no left < n check
        if (a[right] > a[largest]) largest = right;    // no right < n check
        if (largest == i) break;
        std::swap(a[i], a[largest]);
        i = largest;
    }
}

(Answer: the two if lines read a[left] and a[right] without first checking those indices exist. As soon as i reaches a node whose children fall past the end of the array (a leaf, or the last parent with only one child), it reads past the vector: out of bounds, undefined behavior, often a crash. The fix is the guard from the working version: left < n && ... and right < n && ....)

Q1. Define a binary heap and state the properties it must satisfy. Distinguish a min-heap from a max-heap.

Model answer

A binary heap is a binary tree that satisfies two properties:

  • Shape property: it is a complete binary tree. Every level is completely filled except possibly the last, and the last level is filled from left to right with no gaps. This keeps the height at about log n.
  • Heap-order property: a fixed relationship holds between every parent and its children.

The heap-order property is what a min-heap and a max-heap differ on. In a max-heap, every parent is greater than or equal to each of its children, so the largest value is at the root. In a min-heap, every parent is less than or equal to each of its children, so the smallest value is at the root. In both cases there is no ordering between siblings, and an in-order traversal is not sorted; the only guarantee is between a node and its own children.

Q2. Describe the steps to insert a new value into a binary max-heap. Using the max-heap [40, 30, 20, 10, 25, 15] (array form), show the steps to insert the value 35.

Model answer

The steps, keeping both heap properties:

  1. Place the new value in the next free slot, that is, the first empty position on the last level (append it to the end of the array). This keeps the tree complete.
  2. Sift up: compare the new value with its parent. If the new value is larger, swap it with the parent.
  3. Repeat step 2 with the value in its new position, until its parent is greater than or equal to it, or it becomes the root.

Inserting 35 into [40, 30, 20, 10, 25, 15]:

  • Append 35 at index 6: [40, 30, 20, 10, 25, 15, 35]. Its parent is at index (6 - 1) / 2 = 2, which holds 20.
  • 35 > 20, so swap: [40, 30, 35, 10, 25, 15, 20]. 35 is now at index 2, parent (2 - 1) / 2 = 0, which holds 40.
  • 35 < 40, so stop. Final heap: [40, 30, 35, 10, 25, 15, 20].

Two comparisons, one swap; the value climbed one level.

Q3. Describe the steps to delete (extract) the maximum from a binary max-heap. Using the max-heap [40, 30, 20, 10, 25, 15], show the steps to remove the maximum.

Model answer

The steps:

  1. Save the root value; it is the maximum and is what you return.
  2. Move the last element of the array into the root position, then remove that last slot. This keeps the tree complete.
  3. Sift down: compare the value now at the root with its two children. If the larger child is greater than it, swap it with that larger child.
  4. Repeat step 3 at the value's new position, until both its children are smaller than it, or it has no children.

Removing the max from [40, 30, 20, 10, 25, 15]:

  • Save 40 to return. Move the last element (15) to the root and drop the last slot: [15, 30, 20, 10, 25].
  • Children of index 0 are index 1 (30) and index 2 (20). The larger is 30, and 30 > 15, so swap: [30, 15, 20, 10, 25]. 15 is now at index 1.
  • Children of index 1 are index 3 (10) and index 4 (25). The larger is 25, and 25 > 15, so swap: [30, 25, 20, 10, 15]. 15 is now at index 4, a leaf, so stop.
  • Result: max returned is 40, remaining heap is [30, 25, 20, 10, 15].

Q4. Compare a binary heap with a binary search tree (BST). Give one task each is better suited to.

Model answer

Both are binary trees, but they enforce different orderings:

  • BST: for every node, all values in the left subtree are smaller and all in the right subtree are larger. This full ordering makes searching for any given value fast (follow one path down, about O(log n) in a balanced tree) and lets an in-order traversal produce sorted output. A BST is not necessarily a complete tree, so it needs child pointers and can become unbalanced.
  • Heap: only a parent-versus-child rule holds (parent greater than or equal to children in a max-heap), with no order between siblings. It is always a complete tree, so it packs into an array with no pointers. Finding the maximum (or minimum) is O(1) at the root, and insert and extract are O(log n), but searching for an arbitrary value is slow because there is no left-right ordering to guide the search.

Use a BST when you need to search for values or read them in sorted order. Use a heap when you repeatedly need the largest or smallest item, such as a priority queue at a kitchen pass that always sends out the most urgent ticket next.
