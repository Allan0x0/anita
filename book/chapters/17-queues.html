Chapter 17

Queues: first in, first out

The saw only cuts one truss at a time. Jobs pile up on the bench in the order they arrive, and the saw takes the oldest one first: the truss that has waited longest. Nobody jumps the line. That waiting line is a queue, the fairest data structure on the site.

A queue is a line. You add to the back and remove from the front, so the first item in is the first item out. That rule has a name: FIFO (first in, first out). Compare it to a stack, which is last in, first out; a queue is the opposite.

Two markers do all the work:

  • FRONT, the position of the oldest item, the one that leaves next (the truss the saw cuts now).
  • REAR, the position of the newest item, the last one that joined the line (the truss just dropped on the bench).

Four actions are all you ever need:

  • enqueue, add an item at the REAR.
  • dequeue, remove the item at the FRONT.
  • isEmpty, true when the line has nobody in it.
  • isFull, true when the line has no room left.

Here is the saw-job queue as a full program. An array holds the jobs, front and rear are plain integers, and both start at -1 to mean the line is empty.

#include <iostream>
#include <string>
using namespace std;

const int SIZE = 5;
string jobs[SIZE];
int front = -1;
int rear = -1;

bool isEmpty() {
    return front == -1;
}

bool isFull() {
    return rear == SIZE - 1;
}

void enqueue(string job) {
    if (isFull()) {
        cout << "bench full, " << job << " must wait" << endl;
        return;
    }
    if (isEmpty()) {
        front = 0;          // first job opens the line
    }
    rear = rear + 1;        // step REAR to the next free slot
    jobs[rear] = job;
    cout << "queued " << job << endl;
}

void dequeue() {
    if (isEmpty()) {
        cout << "no jobs, saw idle" << endl;
        return;
    }
    cout << "cutting " << jobs[front] << endl;
    if (front == rear) {
        front = -1;         // last job left, reset the line
        rear = -1;
    } else {
        front = front + 1;  // step FRONT forward
    }
}

int main() {
    enqueue("truss-A");
    enqueue("truss-B");
    enqueue("truss-C");
    dequeue();              // cuts truss-A
    dequeue();              // cuts truss-B
    enqueue("truss-D");
    return 0;
}

Build it

Save it, compile, run: g++ -std=c++17 sawqueue.cpp -o sawqueue && ./sawqueue

Truss build step: on a real roof you cut in the order the trusses will be lifted, so the first one off the saw is the first one craned onto the wall plate. Feed jobs into the queue in lift order and the FIFO rule keeps the cutting list matched to the lifting list, no re-sorting on the roof.

The problem with the simple queue. Look at REAR. It only ever moves right. After you dequeue a few jobs the front slots sit empty, but isFull() still fires the moment rear hits the last index. The free space at the front is stranded. You have a five-slot bench reporting "full" with two jobs on it.

The circular queue fixes it. Treat the array as a ring: when a marker runs off the end, wrap it back to index 0 with modulo arithmetic, (rear + 1) % SIZE. Now freed front slots get reused. One catch: with wrapping, "front and rear on the same slot" is ambiguous between empty and full, so keep a count of items and read that instead.

#include <iostream>
#include <string>
using namespace std;

const int SIZE = 4;
string ring[SIZE];
int front = -1;
int rear = -1;
int itemCount = 0;

bool isEmpty() {
    return itemCount == 0;
}

bool isFull() {
    return itemCount == SIZE;
}

void enqueue(string job) {
    if (isFull()) {
        cout << "ring full, " << job << " waits" << endl;
        return;
    }
    rear = (rear + 1) % SIZE;   // wrap past the end
    ring[rear] = job;
    if (front == -1) {
        front = 0;
    }
    itemCount = itemCount + 1;
    cout << "in  " << job << endl;
}

void dequeue() {
    if (isEmpty()) {
        cout << "ring empty" << endl;
        return;
    }
    cout << "out " << ring[front] << endl;
    front = (front + 1) % SIZE; // wrap past the end
    itemCount = itemCount - 1;
}

int main() {
    enqueue("A");
    enqueue("B");
    enqueue("C");
    dequeue();      // frees slot 0
    dequeue();      // frees slot 1
    enqueue("D");
    enqueue("E");   // reuses a wrapped slot, no false "full"
    return 0;
}

A queue with a linked list needs no SIZE at all. Each job is a node; front and rear are pointers. Enqueue links a new node onto the rear; dequeue unlinks the front node and frees it. It is never "full" until the machine runs out of memory, so isFull disappears.

#include <iostream>
#include <string>
using namespace std;

struct Node {
    string job;
    Node* next;
};

Node* front = nullptr;
Node* rear = nullptr;

bool isEmpty() {
    return front == nullptr;
}

void enqueue(string job) {
    Node* n = new Node;
    n->job = job;
    n->next = nullptr;
    if (isEmpty()) {
        front = n;
        rear = n;
    } else {
        rear->next = n;   // link onto the back
        rear = n;
    }
    cout << "queued " << job << endl;
}

void dequeue() {
    if (isEmpty()) {
        cout << "queue empty" << endl;
        return;
    }
    Node* old = front;
    cout << "serving " << front->job << endl;
    front = front->next;
    if (front == nullptr) {
        rear = nullptr;   // line is now empty
    }
    delete old;           // free the served node
}

int main() {
    enqueue("view-point");
    enqueue("waterfall");
    dequeue();            // serving view-point
    enqueue("old-fort");
    dequeue();            // serving waterfall
    dequeue();            // serving old-fort
    dequeue();            // queue empty
    return 0;
}

Build it

g++ -std=c++17 llqueue.cpp -o llqueue && ./llqueue

Same theme, different job: a tour bus visits stops in the order tourists booked them. Book a stop, it joins the rear; arrive at the front stop, it leaves the queue. The linked-list version grows and shrinks with the day's bookings, no fixed bench size to guess up front.

Exam questions

Q1. Define the terms FRONT and REAR as used in a queue.

Model answer

FRONT is the position (index or pointer) of the oldest item in the queue, the next one to be removed by a dequeue. REAR is the position of the newest item, where the last enqueue placed it and where the next enqueue will add. In FIFO order, items leave at FRONT and join at REAR. When FRONT and REAR both signal no items (for an array queue, both set to -1), the queue is empty.

Q2. Write the algorithm for enqueue on a simple array queue that holds up to SIZE items.

Model answer

enqueue(item):
    if rear == SIZE - 1:        // no room at the back
        report "queue full"
        stop
    if front == -1:             // queue was empty
        front = 0
    rear = rear + 1             // move REAR to next slot
    queue[rear] = item          // store the item

Key points: refuse when full (rear == SIZE - 1), open the line by setting front = 0 on the first item, then advance REAR and store. Removal is the mirror: read queue[front], then advance FRONT, resetting both to -1 when the last item leaves.

Q3. Implement a queue using an array in C++, with working enqueue, dequeue, isFull and isEmpty operations.

Model answer

#include <iostream>
using namespace std;

const int SIZE = 5;
int q[SIZE];
int front = -1;
int rear = -1;

bool isEmpty() { return front == -1; }
bool isFull()  { return rear == SIZE - 1; }

void enqueue(int x) {
    if (isFull()) { cout << "full" << endl; return; }
    if (isEmpty()) front = 0;
    rear = rear + 1;
    q[rear] = x;
}

int dequeue() {
    if (isEmpty()) { cout << "empty" << endl; return -1; }
    int x = q[front];
    if (front == rear) { front = -1; rear = -1; }
    else front = front + 1;
    return x;
}

int main() {
    enqueue(10);
    enqueue(20);
    cout << dequeue() << endl;   // 10
    cout << dequeue() << endl;   // 20
    return 0;
}

The two guards keep it safe: isFull stops an overflow past the last index, isEmpty stops a read from an empty queue.

Q4. Implement a queue using a linked list in C++.

Model answer

#include <iostream>
using namespace std;

struct Node { int data; Node* next; };
Node* front = nullptr;
Node* rear = nullptr;

bool isEmpty() { return front == nullptr; }

void enqueue(int x) {
    Node* n = new Node;
    n->data = x;
    n->next = nullptr;
    if (isEmpty()) { front = n; rear = n; }
    else { rear->next = n; rear = n; }
}

int dequeue() {
    if (isEmpty()) return -1;
    Node* old = front;
    int x = front->data;
    front = front->next;
    if (front == nullptr) rear = nullptr;
    delete old;
    return x;
}

int main() {
    enqueue(1);
    enqueue(2);
    cout << dequeue() << endl;   // 1
    cout << dequeue() << endl;   // 2
    return 0;
}

No fixed size and no isFull: the queue grows with new and shrinks with delete. Enqueue links onto the rear; dequeue unlinks the front and frees it, resetting rear to nullptr when the last node leaves.

Q5. Compare a simple (linear) array queue with a circular queue.

Model answer

  • Simple queue: REAR only moves forward and never returns. Once REAR reaches the last index the queue reports full, even when dequeues have freed slots at the front. That free space is wasted unless you shift every item down, which is slow.
  • Circular queue: the array is treated as a ring. Markers wrap with (index + 1) % SIZE, so freed front slots are reused and the whole array stays available. It needs a count (or a spare slot) to tell empty from full, since FRONT meeting REAR is otherwise ambiguous.

In short: the circular queue uses the array fully at the cost of a little extra bookkeeping; the simple queue is easier to write but wastes space.

Q6. Give two real-world uses of a queue.

Model answer

  • Print spooling: documents sent to a shared printer are held in a queue and printed in the order they arrived, first come first served.
  • Job or task scheduling: a saw, a CPU, or a service counter takes waiting jobs in arrival order, so the oldest request is handled next and nobody is starved.

Both rely on FIFO fairness: the item that has waited longest is served next.
