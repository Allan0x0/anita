Day 1 · Arrays & strings recap

A fixed-size sequence, and a loop that touches it once

An array is N same-type slots sitting back to back in memory, a fixed size you decide up front. The cut-list was this from day one: an array of member lengths. A string is just a char array with a NUL byte ('\0') marking where it ends, so a label like "rafter" is a small array too.

Any loop that visits every slot once, print it, sum it, compare it, does N units of work for N slots. That is O(n), linear: double the array, double the work. Nothing about arrays or strings breaks that rule; it is the baseline every later structure gets compared against.

Day 2 · Structs & pointers recap

A struct models a thing; a pointer is an address

A struct bundles related fields under one name. struct Member models one truss piece: a length, an angle, a type. It is a way to say "these three values belong together" instead of tracking three loose variables.

A pointer holds an address, not a value: &m reads as "the address of m". Once a pointer has that address, -> reaches through it to read or change the fields directly, no copy made. This is the hinge unit: everything from linked lists onward is a struct with a pointer field inside it, pointing at another struct of the same kind.

Day 3 · Lists, stacks & queues recap

One sequence idea, three shapes for three jobs

A linked list is a dynamic sequence: each node holds a value and a pointer to the next node, so it grows without a fixed size the way an array needs. A stack serves LIFO, last in first out: the last cut undone is the last one made, good for undo. A queue serves FIFO, first in first out: the first saw job queued is the first one run, good for a fair schedule.

Same underlying sequence, three access rules. The exam question is rarely "what is a stack", it is "which one fits this job": undo history wants LIFO, a print queue wants FIFO, a growing bill-of-materials wants a plain list.

Day 4 · Sorting & searching recap

O(n squared) vs O(n log n), and why binary search needs sorted input

Bubble sort compares nearly every pair to settle the order: O(n squared), cost grows with the square of the size. Faster sorts like quicksort split the work and recurse, landing at O(n log n) on average, a real win once n gets large.

Binary search is O(log n), but only works on sorted input: each comparison halves the range left to check. Feed it unsorted data and the halving logic breaks; you would need a linear scan, O(n), instead. Sort once, search many times, is the trade that makes binary search worth it.

Day 6 · Full efficiency recap

The two exam targets: pick the structure, then cost it

Every unit this term reduces to two questions. First, pick the structure: does the job need order preserved (array, list), LIFO undo (stack), FIFO service (queue), or fast search over ordered data (sorted array, BST)? Second, analyse its cost: what does insert, search, and traverse cost in Big-O for that structure?
