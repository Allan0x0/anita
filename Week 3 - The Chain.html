Day 1 · Pointer walk

A pointer can walk an array by itself

Week 2 reached array boxes with an index: truss[i]. A pointer can reach the same boxes without one. *(truss + i) means the same thing as truss[i]: step i boxes from the start, then read what is there.

A pointer variable can also move on its own. If p points at a Member, p++ moves it to point at the next Member, no index kept anywhere. The array and the walking pointer reach the exact same data.

The code

truss itself already behaves like a pointer to its first box, so p = truss; starts p at box 0 with no & needed.

Day 2 · Why arrays hurt

Insert mid-array means shifting everything after it

An array is boxes in a row with no gaps. To insert a Member in the middle, every Member after that spot has to slide one box right first, to open a gap. Delete works the same way in reverse: slide everything left to close the gap.

Sliding k Members costs k moves. In the worst case (insert at the front) that is n moves for n Members already in the array: O(n), just for one insert.

The code

Inserting at the front shifts every existing Member. Inserting at the end shifts none. The cost depends on where.

Build it

Run it. Then write a delete_at(truss, &n, pos) that shifts everything after pos left by one, and print the shift count.

Day 3 · The node

A struct that points to another struct

A node is a struct with a pointer to another struct of its own type: struct Node { float length; struct Node *next; };. It is self-referential: the definition of Node mentions Node, through a pointer to it.

Chain nodes by pointing one node's next at the next node. The last node's next is NULL: a special address meaning "nothing here", the signal to stop walking.

The code

Three separate variables, a, b, c, become one chain purely because each next holds the address of the following one.

Build it

Run it. Then add a fourth node, d, and link it onto the end of the chain so the walk prints four lines.

Day 4 · Build the chain

The BOM as a linked list, built with malloc

Hand-named nodes only get you so far; a real Bill-of-Materials (BOM) needs nodes made on demand. malloc, from <stdlib.h>, allocates one Node on the heap and hands back its address. free gives that memory back when you are done.

Build the list by making a node, pointing the previous node's next at it, and moving a tail pointer forward. Walk it the same way as Day 3: follow next until NULL.

The code

Save the next pointer before you free the current node; freeing first would leave you with no way to reach what came after.

Build it

Run it. Then write count_nodes(head) that walks the list and returns how many nodes it has.

Day 5 · Insert / delete

Splice a node in or out by repointing next

Once you already hold the spot, inserting into a linked list is not a shift, it is pointer surgery: the new node's next takes the old next, and the earlier node's next is repointed at the new node. Two pointer writes, done: O(1).

Delete works the same way around: relink the node before the target so its next skips over the target, then free the target. No other node moves.

The code

No box slides. Only next fields change hands, so the cost does not depend on how many nodes come after the splice point.

Build it

Run it. Then write insert_before(head, target, node) using a trailing pointer that walks one step behind, since a singly linked list has no way back.

Day 6 · Tie it together

Array vs linked list: an honest trade-off

Neither structure wins outright. An array gives instant access by index but pays for insert and delete with shifting. A linked list splices for free once you hold the spot, but finding that spot means walking from the head, and there is no way to jump straight to node k.

OperationArrayLinked list
Read by indexO(1)O(n)
Insert / delete at a known spotO(n) (shift)O(1) (relink)
Find a spot by valueO(n)O(n)
Extra memory per itemnoneone pointer

The code

Picking a structure is picking which operation you plan to do most: mostly reads by index, an array; mostly inserts and deletes at known spots, a list.
