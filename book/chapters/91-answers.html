PAPER 1: MODEL ANSWERS

Q1 (a) Array versus linked list: memory and insertion cost. [10]

Model answer

Memory allocation. An array is one contiguous block of memory, sized when it is created; all its elements sit side by side and are reached by index arithmetic. A linked list allocates each node separately on the heap; the nodes can sit anywhere in memory and are joined only by pointers, so the list can grow one node at a time without reserving a block up front. [5]

Insertion and deletion in the middle. In an array, adding or removing an element in the middle means shifting every element after it up or down by one slot to keep the block contiguous, which costs O(n) moves. In a linked list, once you hold the node before the target you insert or delete by re-pointing a couple of pointers, which is O(1); the cost is that you first have to walk the list to reach that position. [5]

Q1 (b) Reverse a string in place. [15]

Model answer

Swap the two ends and walk inward until the two indices meet. No second string is allocated.

#include <iostream>
#include <string>

void reverseInPlace(std::string& s) {
    int i = 0;
    int j = static_cast<int>(s.size()) - 1;
    while (i < j) {
        char tmp = s[i];
        s[i] = s[j];
        s[j] = tmp;
        i++;
        j--;
    }
}

int main() {
    std::string word;
    std::cout << "Enter a word: ";
    std::cin >> word;
    reverseInPlace(word);
    std::cout << "Reversed: " << word << "\n";
    return 0;
}

Award up to 15: correct two-pointer loop [8], swap without a second string [4], working main that reads and prints [3].

Q2 (a) Define a stack; principle; two applications. [10]

Model answer

A stack is a linear data structure in which elements are added and removed at one end only, called the top. It obeys the Last-In, First-Out (LIFO) principle: the most recently pushed element is the first one popped. The two core operations are push (add to the top) and pop (remove from the top). [4]

Two applications: (1) the function call stack, where each call is pushed and popped as it returns, which is also how recursion is tracked; (2) the undo feature in an editor, where each action is pushed and undo pops the most recent one. (Also acceptable: expression evaluation, or matching brackets.) [6]

Q2 (b) Stack of integers using an array. [15]

Model answer

#include <iostream>

const int CAP = 100;

struct Stack {
    int data[CAP];
    int top;   // index of top element, -1 when empty
};

void init(Stack& s)      { s.top = -1; }
bool isEmpty(const Stack& s) { return s.top == -1; }
bool isFull(const Stack& s)  { return s.top == CAP - 1; }

bool push(Stack& s, int value) {
    if (isFull(s)) return false;
    s.data[++s.top] = value;
    return true;
}

bool pop(Stack& s, int& out) {
    if (isEmpty(s)) return false;
    out = s.data[s.top--];
    return true;
}

int main() {
    Stack s;
    init(s);
    push(s, 10);
    push(s, 20);
    push(s, 30);

    int x;
    while (pop(s, x)) {
        std::cout << x << "\n";   // prints 30, 20, 10 (LIFO)
    }
    std::cout << "empty? " << (isEmpty(s) ? "yes" : "no") << "\n";
    return 0;
}

Award: correct top tracking and push/pop [8], isEmpty and isFull guards against overflow and underflow [4], working demonstration [3].

Q3 (a) Explain Big-O with an example. [10]

Model answer

Big-O notation describes how the running time (or memory) of an algorithm grows as the input size n grows, keeping only the dominant term and dropping constants. It is an upper bound on the growth rate, so it tells you the worst that will happen as n gets large, not the exact time in seconds. [5]

Example: linear search through an unsorted array of n items looks at each item once, so in the worst case it does n comparisons and is O(n). If the array is ten times larger, the work is about ten times greater. Binary search on a sorted array halves the range each step, so it is O(log n): ten times more data adds only a few extra steps. [5]

Q3 (b) Complexity of the three snippets. [15]

Model answer

Snippet 1: O(n squared). The outer loop runs n times and for each of those the inner loop runs n times, so the body runs n times n, which is n squared, times. [5]

Snippet 2: O(log n). The counter i doubles every iteration (1, 2, 4, 8, ...), so the number of steps before i reaches n is log base 2 of n. Multiplying instead of adding is the signature of a logarithmic loop. [5]

Snippet 3: O(n). A single loop that runs once per element, doing constant work each time, is linear in n. [5]

Q4 (a) Merge Sort steps and complexity. [10]

Model answer

Merge Sort is a divide and conquer sort. Its steps: (1) divide the array into two halves; (2) recurse, sorting each half the same way, until a half has one element (already sorted); (3) merge the two sorted halves into one sorted array by repeatedly taking the smaller of the two front elements. [6]

Complexity: the array is split into log n levels and each level does O(n) work to merge, so the time is O(n log n) in the best, average, and worst case alike. It needs O(n) extra memory for the merge. [4]

Q4 (b) Binary search on ten sorted ints. [15]

Model answer

#include <iostream>

// Returns the index of target in the sorted array a[0..n-1], or -1 if absent.
int binarySearch(const int a[], int n, int target) {
    int lo = 0;
    int hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target)      return mid;
        else if (a[mid] < target)  lo = mid + 1;
        else                       hi = mid - 1;
    }
    return -1;
}

int main() {
    int a[10] = {3, 8, 12, 17, 23, 31, 44, 55, 68, 90};
    int target = 44;

    int pos = binarySearch(a, 10, target);
    if (pos != -1)
        std::cout << target << " found at index " << pos << "\n";
    else
        std::cout << target << " not found\n";
    return 0;
}

Award: correct halving loop with lo/hi/mid [8], overflow-safe mid and correct comparisons [4], working main that reports index or not-found [3].

Q1 (a) Define an ADT; two examples. [10]

Model answer

An abstract data type (ADT) is a description of a data type by the operations it offers and the rules those operations obey, without saying how they are implemented. It is the "what", separated from the "how": a user of the ADT relies only on the interface, so the implementation can change underneath without breaking the caller. [4]

Examples: (1) a Stack ADT (push, pop, top, isEmpty) can be implemented with an array or a linked list; (2) a Queue ADT (enqueue, dequeue, front) can be implemented with an array or a linked list. (Also acceptable: List, Map, or Priority Queue with a heap.) [6]

Q2 (a) Define a queue; FRONT and REAR; simple versus circular. [10]

Model answer

A queue is a linear structure that obeys First-In, First-Out (FIFO): elements are added at one end and removed at the other, so the first in is the first out. FRONT is the end from which elements are removed (dequeued); REAR is the end at which elements are added (enqueued). [5]

In a simple (linear) array queue, FRONT and REAR only move forward, so once REAR reaches the last slot the queue looks full even though the slots freed at the front are wasted. A circular queue fixes this by letting REAR and FRONT wrap around to index 0 using modulo arithmetic, so the freed front slots are reused and the whole array holds data. [5]

Q2 (b) Queue of integers using an array. [15]

Model answer

A circular array queue, so freed slots at the front are reused.

#include <iostream>

const int CAP = 100;

struct Queue {
    int data[CAP];
    int front;   // index of first element
    int count;   // number of elements held
};

void init(Queue& q)          { q.front = 0; q.count = 0; }
bool isEmpty(const Queue& q)  { return q.count == 0; }
bool isFull(const Queue& q)   { return q.count == CAP; }

bool enqueue(Queue& q, int value) {
    if (isFull(q)) return false;
    int rear = (q.front + q.count) % CAP;
    q.data[rear] = value;
    q.count++;
    return true;
}

bool dequeue(Queue& q, int& out) {
    if (isEmpty(q)) return false;
    out = q.data[q.front];
    q.front = (q.front + 1) % CAP;
    q.count--;
    return true;
}

int main() {
    Queue q;
    init(q);
    enqueue(q, 1);
    enqueue(q, 2);
    enqueue(q, 3);

    int x;
    while (dequeue(q, x)) {
        std::cout << x << "\n";   // prints 1, 2, 3 (FIFO)
    }
    return 0;
}

Award: correct enqueue/dequeue with wrap-around [8], isFull/isEmpty guards [4], working demo [3].

Q3 (a) What is recursion; three properties. [10]

Model answer

Recursion is when a function solves a problem by calling itself on a smaller version of the same problem, until the problem is small enough to answer directly. [4]

Three properties every correct recursive solution has: (1) a base case that stops the recursion without another call; (2) a recursive case that calls the function on a strictly smaller input; (3) progress toward the base case on every call, so the recursion is guaranteed to end. [6]

Q4 (b) What "balanced" means; a self balancing tree. [10]

Model answer

A binary search tree is balanced when the left and right subtrees of every node have heights that differ by little, so the whole tree stays short and bushy rather than tall and lopsided. Balance matters because search, insert, and delete all take time proportional to the height: a balanced tree of n nodes has height about log n, giving O(log n) operations, whereas a degenerate tree (values inserted in sorted order) becomes a straight line of height n, degrading to O(n), no better than a list. [6]

One self balancing search tree is the AVL tree: it stores a balance factor at each node and, after an insert or delete unbalances a node, it performs rotations to restore the height difference to at most one. (A Red-Black tree is also acceptable: it colours nodes red or black and enforces colouring rules that keep the longest path at most twice the shortest.) [4]

PAPER 3: MODEL ANSWERS

Q1 (a) Pointers; & and *; why a list needs them. [10]

Model answer

A pointer is a variable whose value is the memory address of another variable. The address-of operator & takes a variable and yields its address, so &x is "where x lives". The dereference operator * takes a pointer and yields the variable it points to, so *p is "the thing at the address in p", which can be read or assigned. [6]

A linked list needs pointers because its nodes are allocated separately and are not next to each other in memory. Each node stores a pointer to the next node, and that chain of pointers is the only thing that keeps the list together; following the pointers is how you walk from one node to the next. [4]

Q1 (b) Singly linked list, insert at beginning. [15]

Model answer

#include <iostream>

struct Node {
    int value;
    Node* next;
};

// Insert a new node at the front; returns the new head.
Node* insertFront(Node* head, int value) {
    Node* n = new Node;
    n->value = value;
    n->next = head;
    return n;
}

void print(Node* head) {
    for (Node* p = head; p != nullptr; p = p->next)
        std::cout << p->value << " ";
    std::cout << "\n";
}

int main() {
    Node* head = nullptr;
    head = insertFront(head, 10);
    head = insertFront(head, 20);
    head = insertFront(head, 30);

    print(head);   // 30 20 10 (last inserted is at the front)

    // free the list
    while (head != nullptr) {
        Node* tmp = head;
        head = head->next;
        delete tmp;
    }
    return 0;
}

Q2 (a) Hash table; hash function; two collision techniques. [10]

Model answer

A hash table stores key-value pairs in an array and aims for near-constant-time insert and lookup. A hash function turns a key into an array index (for integers, commonly key % tableSize); ideally it spreads keys evenly across the slots. A collision happens when two keys hash to the same slot. [4]

Two collision resolution techniques: (1) chaining (separate chaining), where each slot holds a linked list and colliding keys are appended to that list; (2) open addressing with linear probing, where on a collision you scan forward slot by slot (wrapping around) until an empty slot is found. (Quadratic probing and double hashing are also acceptable.) [6]

Q2 (b) Hash table with linear probing. [15]

Model answer

#include <iostream>

const int SIZE = 10;
const int EMPTY = -1;   // sentinel for an unused slot

struct HashTable {
    int slots[SIZE];
};

void init(HashTable& h) {
    for (int i = 0; i < SIZE; i++) h.slots[i] = EMPTY;
}

// Insert key using modulo hash + linear probing. Returns false if table full.
bool insert(HashTable& h, int key) {
    int start = key % SIZE;
    for (int i = 0; i < SIZE; i++) {
        int idx = (start + i) % SIZE;
        if (h.slots[idx] == EMPTY) {
            h.slots[idx] = key;
            return true;
        }
    }
    return false;   // table full
}

// Return the index of key, or -1 if absent.
int search(const HashTable& h, int key) {
    int start = key % SIZE;
    for (int i = 0; i < SIZE; i++) {
        int idx = (start + i) % SIZE;
        if (h.slots[idx] == EMPTY) return -1;   // empty slot: key not present
        if (h.slots[idx] == key)   return idx;
    }
    return -1;
}

int main() {
    HashTable h;
    init(h);
    int keys[] = {23, 43, 13, 27};   // 23,43,13 all hash to slot 3: collisions
    for (int k : keys) insert(h, k);

    std::cout << "43 at index " << search(h, 43) << "\n";
    std::cout << "99 at index " << search(h, 99) << "\n";   // -1, absent
    return 0;
}

Award: modulo hash and probing loop that wraps [8], correct search that stops at an empty slot [4], working demo showing a collision [3].

Q3 (a) Divide and conquer versus greedy. [10]

Model answer

Divide and conquer solves a problem by splitting it into smaller subproblems of the same kind, solving each (usually by recursion), then combining their results into the answer for the whole. [3]

Greedy builds a solution one step at a time, at each step taking the choice that looks best right now (the local optimum), never reconsidering an earlier choice. [3]

Contrast. Divide and conquer breaks the problem down and combines partial answers, often recursively; greedy makes one forward pass of locally optimal choices and does no combining or backtracking. Greedy is usually faster but only gives the correct global answer for problems that have the greedy-choice property. Example suited to divide and conquer: Merge Sort. Example suited to greedy: finding a minimum spanning tree with Prim's or Kruskal's algorithm (or making change with the fewest coins). [4]

Q3 (b) Quick Sort steps; partition function. [15]

Model answer

Steps. (1) Choose a pivot element. (2) Partition the array so that all elements less than the pivot come before it and all greater come after it; the pivot is now in its final sorted position. (3) Recursively Quick Sort the part to the left of the pivot and the part to the right. The base case is a sub-array of size zero or one, which is already sorted. [6]

The partition function below uses the last element as the pivot (Lomuto scheme) and returns the pivot's final index. A full program is shown so it compiles and runs.

#include <iostream>

void swap(int& a, int& b) { int t = a; a = b; b = t; }

// Lomuto partition: pivot is the last element a[high].
int partition(int a[], int low, int high) {
    int pivot = a[high];
    int i = low - 1;                 // boundary of the "less than pivot" region
    for (int j = low; j < high; j++) {
        if (a[j] < pivot) {
            i++;
            swap(a[i], a[j]);
        }
    }
    swap(a[i + 1], a[high]);         // put pivot in its final place
    return i + 1;                    // pivot's index
}

void quickSort(int a[], int low, int high) {
    if (low < high) {
        int p = partition(a, low, high);
        quickSort(a, low, p - 1);
        quickSort(a, p + 1, high);
    }
}

int main() {
    int a[] = {29, 10, 14, 37, 13};
    int n = 5;
    quickSort(a, 0, n - 1);
    for (int i = 0; i < n; i++) std::cout << a[i] << " ";
    std::cout << "\n";   // 10 13 14 29 37
    return 0;
}

Award: correct step description [6], correct partition (pivot choice, boundary index, final swap, returned index) [9].

Q4 (a) Graphs; directed versus undirected; BFS with an example. [15]

Model answer

A graph is a set of vertices (nodes) joined by edges. In an undirected graph an edge has no direction, so an edge between A and B can be travelled both ways. In a directed graph (digraph) each edge has a direction, an arrow from one vertex to another, so an edge A to B does not let you travel B to A. [6]

Breadth-First Search (BFS) visits a graph in layers outward from a start vertex: first the start, then all its direct neighbours, then their unvisited neighbours, and so on. It uses a queue: enqueue the start and mark it visited; then repeatedly dequeue a vertex, and enqueue each of its unvisited neighbours (marking them visited as they are enqueued). [5]

Worked example starting at A. Queue steps: visit A, enqueue its neighbours B and C; dequeue B, enqueue its unvisited neighbour D; dequeue C (D already queued); dequeue D. BFS order: A, B, C, D. Award: graph definition and directed vs undirected [6], BFS explanation [5], correct worked order with diagram [4].

Q4 (b) Heaps; properties; min versus max. [10]

Model answer

A heap is a complete binary tree (every level full except possibly the last, which fills left to right) that satisfies the heap property: each node compares in a fixed way with its children. Because it is complete, a heap is normally stored in an array, where the children of index i sit at 2i+1 and 2i+2. Its properties: it is always complete, so its height is about log n; the extreme value (largest or smallest) is always at the root; and insert and remove-root both cost O(log n). It is the usual implementation of a priority queue. [6]

In a max-heap, every parent is greater than or equal to its children, so the maximum is at the root. In a min-heap, every parent is less than or equal to its children, so the minimum is at the root. [4]
