Chapter 18

Sorting

You have a pile of cut boards for the roof, jumbled: 2.1m, 4.8m, 1.2m, 3.6m, and on and on. The foreman wants the longest laid out first so the ridge goes up before anyone reaches for a short one. Right now the pile is in the order it left the saw, which is no order at all. Sorting is how you turn that jumble into a line, longest to shortest, so nobody wastes a 4.8m board on a 1.2m job and leaves an offcut on the ground.

Sorting means putting a list in order: smallest to largest, largest to smallest, A to Z. The list starts jumbled; you finish with it arranged. This chapter shows three ways to do it by hand and in code: bubble sort, selection sort, and insertion sort. All three reach the same sorted list; they differ in how they get there and how much work they do. We measure that work with Big-O, the count of comparisons as the list grows, and we look at the best, average, and worst case for each.

Bubble sort: swap neighbours until nothing moves

Bubble sort walks the list comparing each pair of neighbours. If they are out of order it swaps them. One full walk is a pass. Each pass floats the next-largest value up to its place, the way a bubble rises; you repeat passes until a whole pass makes no swaps, which means the list is sorted. Below we sort a small cut-list into ascending metres so it is easy to trace.

#include <iostream>

// bubble sort: ascending, stops early when a pass makes no swaps
int main() {
    double cut[6] = {2.1, 4.8, 1.2, 3.6, 2.4, 1.8};
    int n = 6;

    for (int pass = 0; pass < n - 1; pass = pass + 1) {
        bool swapped = false;
        for (int i = 0; i < n - 1 - pass; i = i + 1) {
            if (cut[i] > cut[i + 1]) {
                double tmp = cut[i];
                cut[i] = cut[i + 1];
                cut[i + 1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) {
            break;   // a clean pass means the list is already sorted
        }
    }

    for (int i = 0; i < n; i = i + 1) {
        std::cout << cut[i] << "m ";
    }
    std::cout << std::endl;
    return 0;
}

Build it: sort the cut-list before you climb the roof

Save the program as cutlist.cpp and run it:

g++ -std=c++17 cutlist.cpp -o cutlist && ./cutlist

It prints 1.2m 1.8m 2.1m 2.4m 3.6m 4.8m. On site this is the step between cutting and raising: feed the day's cut lengths in jumbled, get them back in order, then lay the longest boards on the ridge first and match the shorts to the short jobs. Nothing sound gets sawn down into an offcut.

Selection sort: find the smallest, put it in front

Selection sort is how most people sort by hand without thinking about it. Scan the whole unsorted part, find the smallest value, and swap it to the front. Now the front is settled; repeat on the rest. It makes exactly one swap per pass, which is handy when moving items is expensive, but it always scans the full remainder even when the list is already sorted.

#include <iostream>
#include <string>

// selection sort: order tourist stops by distance in km
int main() {
    std::string stop[5] = {"Falls", "Ruins", "Dune", "Lake", "Cave"};
    int km[5] = {120, 45, 300, 80, 15};
    int n = 5;

    for (int i = 0; i < n - 1; i = i + 1) {
        int smallest = i;
        for (int j = i + 1; j < n; j = j + 1) {
            if (km[j] < km[smallest]) {
                smallest = j;
            }
        }
        // one swap: bring the nearest remaining stop to the front
        int tk = km[i];      km[i] = km[smallest];      km[smallest] = tk;
        std::string ts = stop[i]; stop[i] = stop[smallest]; stop[smallest] = ts;
    }

    for (int i = 0; i < n; i = i + 1) {
        std::cout << stop[i] << " (" << km[i] << "km)" << std::endl;
    }
    return 0;
}

That prints the tour nearest-first: Cave (15km), Ruins (45km), Lake (80km), Falls (120km), Dune (300km). Note the name array moves in lockstep with the distance array, so each stop keeps its own number.

Insertion sort: slot each new item into place

Insertion sort is how you sort a hand of cards. Hold the left part sorted; take the next item and slide it left, past everything larger, until it drops into its slot. When the incoming item is already bigger than its left neighbour it stops at once, so a nearly-sorted list barely moves. That early stop is why insertion sort is the fastest of the three on lists close to sorted.

#include <iostream>

// insertion sort: order recipe bake temperatures, ascending
int main() {
    int temp[7] = {180, 220, 160, 200, 175, 240, 190};
    int n = 7;

    for (int i = 1; i < n; i = i + 1) {
        int key = temp[i];        // the item to slot in
        int j = i - 1;
        while (j >= 0 && temp[j] > key) {
            temp[j + 1] = temp[j]; // shift the larger one right
            j = j - 1;
        }
        temp[j + 1] = key;         // drop the item into its slot
    }

    for (int i = 0; i < n; i = i + 1) {
        std::cout << temp[i] << " ";
    }
    std::cout << std::endl;
    return 0;
}

Build it: on-site truss step

Compile and run either sort the same way:

Truss build step 4, after cutting: run the day's board lengths through one of these sorts, print the ordered list, and pin it to the timber rack. The crew pulls from the top of the list, longest first for the ridge and rafters, shortest last for the noggins between them. An ordered rack is a rack with no guessing and no cutting a good board short.

How much work: best, average, worst

All three sorts do roughly n comparisons per pass across roughly n passes, so the general cost is O(n squared): double the list, quadruple the work. But the cases differ. The best case is an already-sorted list; the worst case is one sorted exactly backwards; the average case is a random jumble. Bubble and insertion sort can notice an already-sorted list and finish in O(n): bubble sort by making a clean pass, insertion sort by never entering its shift loop. Selection sort cannot; it scans the full remainder every time, so even a sorted list costs it O(n squared).

Challenge: spot the bug

A trainee writes a bubble sort but types the outer loop as for (int pass = 0; pass < n; pass = pass + 1) and the inner as for (int i = 0; i < n; i = i + 1), reading cut[i + 1] each time. The list sorts, but the program sometimes crashes or prints garbage. Why? (Answer: on the last i, i + 1 is n, one past the end of the array. Reading cut[n] is out of bounds. The inner loop must stop at i < n - 1.)

Exam questions

Q1. Write a complete C++ program that reads ten jumbled whole numbers into an array and sorts them into ascending order using insertion sort, then prints the sorted list. You may hard-code the ten numbers.

Model answer

Insertion sort holds the left part sorted and slides each new value left into its slot. Ten values fixed in the array, one pass from index 1 to 9:

#include <iostream>

int main() {
    int a[10] = {37, 12, 88, 4, 61, 25, 9, 70, 43, 18};
    int n = 10;

    for (int i = 1; i < n; i = i + 1) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];   // shift larger values right
            j = j - 1;
        }
        a[j + 1] = key;        // drop key into its slot
    }

    for (int i = 0; i < n; i = i + 1) {
        std::cout << a[i] << " ";
    }
    std::cout << std::endl;
    return 0;
}

It prints 4 9 12 18 25 37 43 61 70 88. The while condition a[j] > key is what keeps the sort ascending; the j >= 0 guard stops it running off the front of the array.

Q2. Compare bubble sort and insertion sort by their best-case, average-case, and worst-case time complexity. State when each best case happens.

Model answer

Both share the same average and worst case and differ only in how their best case arises:

CaseBubbleInsertion
BestO(n)O(n)
AverageO(n squared)O(n squared)
WorstO(n squared)O(n squared)

The best case for both is an already-sorted list. Bubble sort reaches O(n) only if it tracks a swapped flag: the first pass makes no swap, so it stops after one walk of the list. Insertion sort reaches O(n) because each new item is already larger than its left neighbour, so the shift loop never runs; it walks the list once. The worst case for both is a list sorted exactly backwards, where every comparison forces a move, giving O(n squared). In practice insertion sort usually moves fewer items on partly-sorted data, so it is the faster of the two on real-world, nearly-ordered lists like a cut-list that was already close to length order.

Q4. Explain in plain words why selection sort has the same O(n squared) cost on an already-sorted list as on a jumbled one, while bubble and insertion sort can be O(n) on a sorted list.

Model answer

Selection sort's job each pass is to find the smallest value in the unsorted remainder, and the only way to be sure it has found the smallest is to look at every remaining value. It cannot tell that the list is already sorted, because it never compares neighbours; it always scans the full remainder. So the number of comparisons is fixed by the list length, about n plus (n minus 1) plus (n minus 2) and so on, which is O(n squared) no matter the starting order. Bubble and insertion sort compare adjacent items, so they can detect order locally: bubble sort sees a whole pass with no swaps and stops; insertion sort finds each item already in place and skips its shift loop. On a sorted list each does about n comparisons and no moves, which is O(n). The lesson: a sort that looks at local order can shortcut, one that always does a global scan cannot.
