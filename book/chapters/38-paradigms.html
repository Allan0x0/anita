Chapter 38

Paradigms: ADTs, Greedy, Divide and Conquer

A carpenter does not think in nails and glue while sketching a roof. He thinks "truss here, beam there", and only later decides how each is joined. Software has the same two levels. First you say what a thing must do (a stack of plates: put one on top, take the top one off). Only after do you pick how to build it (an array, a linked list). This chapter is about that split, and about two ways of thinking that solve whole families of problems: greedy, and divide and conquer. These turn up on the exam again and again, so it pays to see them clearly once.

An abstract data type (ADT) is a set of values plus the operations allowed on them, described by what they do, not how they are stored. The ADT is the menu; the data structure is the kitchen. You order "a stack": push, pop, look at the top. Whether the cook builds it from an array or a linked list is the kitchen's business, and you can swap kitchens without changing a single order.

Two examples you already know, each an ADT mapped onto real structures:

  • Stack ADT. Operations: push (add on top), pop (remove the top), top (peek). Rule: last in, first out (LIFO), like a stack of clean plates. It can be implemented with an array (a counter marks the top) or with a singly linked list (the head is the top).
  • Queue ADT. Operations: enqueue (join the back), dequeue (leave the front). Rule: first in, first out (FIFO), like the line at a food stall. It can be implemented with an array (two indices, front and back) or with a linked list (head is the front, tail is the back).

Same idea both times: the ADT names the promise, the structure keeps it. Change the structure and the promise still holds.

Greedy. A greedy method builds an answer one step at a time, and at each step takes the choice that looks best right now, never going back to reconsider. The principle: make the locally best choice and hope it adds up to the globally best answer. It is fast and simple, and for some problems it is exactly right.

The classic example is making change with the fewest coins. To pay 87 cents, take the biggest coin that still fits, again and again: 50, then 20, then 10, then 5, then 1, then 1. Each grab is the locally best move, and for ordinary coin sets it lands on the fewest coins.

#include <iostream>
#include <vector>

int main() {
    std::vector<int> coins = {50, 20, 10, 5, 1}; // largest first
    int amount = 87;

    std::cout << "change for " << amount << ": ";
    for (int coin : coins) {
        while (amount >= coin) {   // take this coin while it still fits
            std::cout << coin << ' ';
            amount -= coin;
        }
    }
    std::cout << std::endl;
    return 0;
}

Build it

Save as greedy.cpp, then compile and run:

g++ -std=c++17 greedy.cpp -o greedy && ./greedy

It prints change for 87: 50 20 10 5 1 1. Six coins, chosen without ever looking back.

Greedy is not magic. It only gives the best answer when the problem has the right shape (each local best choice keeps a global best answer reachable). For a coin set like 1, 5, 10, 20, 50 it works. For an odd set like 4, 3, 1 it can fail: greedy pays 6 as 4, 1, 1 (three coins) when 3, 3 (two coins) is fewer. Know one case where greedy wins and one where it loses; the exam likes that contrast.

Divide and conquer. This paradigm has three moves: divide the problem into smaller problems of the same kind, conquer each smaller piece (usually by the same method, so it recurses), then combine the pieces into the full answer. Splitting a big job into halves you can trust, then joining the results, is the whole idea.

Two sorts are built this way:

  • Merge sort. Divide the array into two halves, sort each half, then merge the two sorted halves into one. The work is in the combine step.
  • Quicksort. Pick a pivot, partition the array so smaller values sit left of the pivot and larger ones sit right, then sort each side. The work is in the divide step.

Here is merge sort as a complete program, with the three moves labelled.

#include <iostream>
#include <vector>

// Combine: merge two sorted halves of a into one sorted run.
void merge(std::vector<int>& a, int lo, int mid, int hi) {
    std::vector<int> tmp;
    int i = lo, j = mid + 1;
    while (i <= mid && j <= hi) {
        if (a[i] <= a[j]) tmp.push_back(a[i++]);
        else             tmp.push_back(a[j++]);
    }
    while (i <= mid) tmp.push_back(a[i++]);
    while (j <= hi)  tmp.push_back(a[j++]);
    for (int k = 0; k < (int)tmp.size(); ++k) a[lo + k] = tmp[k];
}

void mergeSort(std::vector<int>& a, int lo, int hi) {
    if (lo >= hi) return;          // one element: already sorted
    int mid = lo + (hi - lo) / 2;  // divide
    mergeSort(a, lo, mid);         // conquer the left half
    mergeSort(a, mid + 1, hi);     // conquer the right half
    merge(a, lo, mid, hi);         // combine
}

int main() {
    std::vector<int> a = {38, 27, 43, 3, 9, 82, 10};
    mergeSort(a, 0, (int)a.size() - 1);
    for (int x : a) std::cout << x << ' ';
    std::cout << std::endl;
    return 0;
}

Build it

g++ -std=c++17 merge.cpp -o merge && ./merge

Prints 3 9 10 27 38 43 82. Same trick as framing a roof in sections on the ground, then lifting each finished section and joining them at the ridge.

Linear versus non-linear structures. A linear structure lays its elements out in a single line, each with one element before it and one after (except the ends). Arrays, linked lists, stacks, and queues are linear: you walk them front to back like beads on a string.

A non-linear structure lets an element connect to many others, so there is no one straight path through it. Trees and graphs are non-linear: a tree node branches to several children, and a graph node can link to any others. A tour route down one road is linear; the full road map, with junctions and loops, is non-linear.

Why data structures matter at all. A data structure is a way of arranging data so the operations you do most are cheap. The same values stored two ways can differ enormously in speed. Numbers in a sorted array can be searched in a handful of steps with binary search; the same numbers in an unsorted heap must be scanned one by one. Choosing the structure to fit the job is the difference between a program that answers instantly and one that crawls. In short: the right structure turns a slow, awkward problem into a fast, simple one, and picking it well is most of what makes a program good.

Challenge (spot where greedy fails)

A stall has only 4c, 3c, and 1c tokens. A tourist needs 6c in change. The greedy rule (take the biggest token that fits, repeat) grabs a 4, then a 1, then a 1: three tokens. Find a payment using fewer tokens, and explain in one line why greedy missed it.

(Answer: 3 + 3 = 6, just two tokens. Greedy missed it because grabbing the 4 first was the locally best move but left a remainder, 2, that no single token could finish cheaply. Greedy never looks back to undo that first grab.)

Q1. Define the term abstract data type (ADT) and give two examples, naming for each a data structure that could implement it.

Model answer

An abstract data type is a description of a set of values together with the operations allowed on them, defined by what the operations do rather than how they are stored. It separates the interface (the promised operations) from the implementation (the underlying data structure), so the structure can change without changing how the type is used.

  • Stack ADT: operations push, pop, and top, following last in, first out (LIFO). It can be implemented with an array (an index marks the top) or a singly linked list (the head node is the top).
  • Queue ADT: operations enqueue and dequeue, following first in, first out (FIFO). It can be implemented with an array (front and back indices) or a linked list (head is the front, tail is the back).

Q2. State the greedy principle and illustrate it with a worked example.

Model answer

The greedy principle: build a solution one step at a time, and at each step take the choice that looks best at that moment, without reconsidering earlier choices. It aims for the global best by making the locally best choice each time.

Example, making 87 cents with coins 50, 20, 10, 5, 1 using the fewest coins. Take the largest coin that still fits, repeatedly: 87 gives a 50 (left 37), a 20 (left 17), a 10 (left 7), a 5 (left 2), then a 1 and a 1 (left 0). Result: 50, 20, 10, 5, 1, 1, which is six coins and the fewest possible for this coin set. (Greedy is only correct for suitable coin sets; for a set such as 4, 3, 1 it can give more coins than the true minimum.)

Q3. Explain the divide-and-conquer paradigm and name two sorting algorithms that use it.

Model answer

Divide and conquer solves a problem in three steps: divide the problem into smaller sub-problems of the same type, conquer each sub-problem (typically by applying the same method recursively until the pieces are trivial), and combine the sub-results into the solution for the whole.

Two sorting algorithms that use it:

  • Merge sort: divide the array into two halves, sort each half, then merge the two sorted halves into one sorted array.
  • Quicksort: choose a pivot, partition the array so smaller values go left and larger values go right of the pivot, then sort each side.

Q4. Distinguish between linear and non-linear data structures, giving two examples of each.

Model answer

In a linear data structure the elements are arranged in a single sequence, so each element has exactly one predecessor and one successor apart from the first and last. There is one straight path through all of them. Examples: arrays and linked lists (also stacks and queues).

In a non-linear data structure an element may be connected to more than one other element, so the data branches and there is no single straight path through it. Examples: trees and graphs. A tree node can have several children; a graph node can link to many other nodes and the links may form loops.

Q5. Explain the purpose and importance of data structures in programming.

Model answer

A data structure is a way of organising and storing data so that the operations performed on it (such as insert, delete, search, and traverse) can be carried out efficiently. Its purpose is to match the arrangement of the data to the way the program uses it.

It is important because the choice of structure directly affects how fast and how simply a program runs. The same data held in different structures can give very different performance: searching a sorted array with binary search takes only a few steps, while scanning an unsorted list checks every element. A good structure can turn a slow, complicated task into a fast, straightforward one, so selecting the right one is a large part of writing efficient software.
