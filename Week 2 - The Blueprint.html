The Blueprint

Unit 3: Structures. Unit 4: Pointers (start). A struct bundles related fields, length, angle, type, into one Member. A truss is an array of Members. You will build one, walk it, and reach into it through a pointer.

Day 1 · Declare

A struct bundles fields into one box

A struct groups several fields under one name, even when the fields are different types. A truss Member needs a length, an angle, and a type: three values, one struct.

struct Member { float length; int angle; char type; }; defines the shape. struct Member m; makes one blank Member. Reach a field with a dot: m.length.

The code

The struct Member { ... }; block only defines the shape. It makes no Member by itself; struct Member m; does that.

Build it

Compile and run: gcc -Wall day1_member.c -o day1 then ./day1. Then add a fourth field, e.g. float force;, set it, and print it too.

Day 2 · Initialize

Fill a struct in one line, read its fields

Like an array, a struct can be filled all at once with a struct literal: values in the same order as the fields, in curly braces.

struct Member top_chord = {3.0, 30, 'C'}; sets length, angle, type in one go. After that, each field is a normal variable: read it, print it, or change it with the dot.

The code

The literal order must match the field order: length, then angle, then type.

Build it

Run it. Then make a second Member with your own values and print it too.

Day 3 · The truss

An array of structs, walked in one loop

A truss is not one Member, it is many. The fix is the same one from Week 1: an array, except now each box holds a whole struct instead of one number.

struct Member truss[4]; makes four Members in a row. truss[i].length reaches member i's length. Walking all four is still one loop, still O(n).

The code

Same walk as Week 1's cut-list, one field deeper: truss[i].length instead of cut[i].

Build it

Run it. Then add a 5th Member to the array and update N; the loop just follows.

Day 4 · By value vs by pointer

A copy is safe but wasteful; a pointer shares

Passing a struct to a function by value copies every field in. The function can look at it, but changes inside stay inside; the caller's Member is untouched.

Passing by pointer shares the same Member: no copy, and changes through the pointer really change the caller's data. &web is the address of web, the same & from the on-ramp.

The code

A big struct passed by value copies every field, every call. A pointer is one address: cheap, and it lets the function mutate the real data.

Build it

Run it. Then write a second by-value function that tries to grow the length and prove the caller's copy is unchanged.

Check yourself

Day 5 · Pointers

&x, *p, p->field

A pointer is a variable that holds an address, not a value. int *p = &angle; makes p point at angle. *p reaches the value stored there, in either direction: read it or write it.

For a struct pointer, mp->length is shorthand for (*mp).length: follow the pointer, then reach the field. It is the same idea as Day 4's m->length, spelled out.

The code

& takes an address, * follows one back to a value. They undo each other: *&angle is just angle.

Build it

Run it. Then declare a second int, point p at it instead, and print through p.

Check yourself

Day 6 · Tie it together

Mutate a truss through pointers

Put the week together: a function that takes struct Member * changes one Member for real; a function that takes struct Member truss[] walks and can change many, since an array argument already behaves like a pointer to its first box.

Nothing here is new efficiency-wise: walking the array is still one pass, still O(n). What changed is that the walk now reaches through to the real data, not a copy.

The code

&truss[1] is the address of one Member inside the array: same trick as Day 4, aimed at a single box.

Build it

Run it. Then write void scale_truss(struct Member truss[], int n, float factor) that multiplies every length by factor, and call it from main.

Check yourself
