Chapter 15

Lists and linked lists

Before you cut a single board you write a bill of materials: rafters, then a ridge beam, then gusset plates, then bolts. It is a list, and it grows as the design changes. Halfway through you realise you forgot the centre post, and it has to slot in between the rafters and the ridge beam. On paper you just draw an arrow and squeeze it in. A linked list is that trick in code: a chain of items where each one points to the next, so you can splice a new part into the middle without shuffling everything after it.

A linked list is a chain of small boxes called nodes. Each node holds two things: the data (one part of the bill) and a pointer to the next node. The last node points to nothing, written nullptr (the older word for it is NULL). You keep one pointer, the head, aimed at the first node; from there you can walk the whole chain by following each next. Nothing says the nodes sit side by side in memory. They can be scattered anywhere; the pointers are what hold the order.

In C++ a node is a struct that contains a pointer to its own type. That self-reference is the whole idea: a Part that knows where the next Part lives.

#include <iostream>
#include <string>

struct Part {
    std::string name;   // the data: one line of the bill
    int qty;            // how many of it
    Part* next;         // pointer to the next node, or nullptr at the end
};

int main() {
    Part* head = nullptr;   // an empty list is just a null head
    std::cout << "List starts empty: " << (head == nullptr) << std::endl;
    return 0;
}

Build a list and walk it

To build a list by hand you ask for each node with new, fill its data, and link it to the one before. To read the list back you traverse it: start at the head and keep following next until you fall off the end at nullptr.

#include <iostream>
#include <string>

struct Part {
    std::string name;
    int qty;
    Part* next;
};

int main() {
    // build three nodes: rafters -> ridge -> bolts
    Part* rafter = new Part{"Rafter", 2, nullptr};
    Part* ridge  = new Part{"Ridge beam", 1, nullptr};
    Part* bolts  = new Part{"Bolts", 8, nullptr};
    rafter->next = ridge;
    ridge->next  = bolts;

    Part* head = rafter;

    // traverse: follow next until we hit nullptr
    for (Part* p = head; p != nullptr; p = p->next) {
        std::cout << p->qty << " x " << p->name << std::endl;
    }

    // give the memory back
    delete rafter;
    delete ridge;
    delete bolts;
    return 0;
}

Build it: the truss bill of materials

Step 4 of the truss build is pricing. Save the program above as bom.cpp and run it:

g++ -std=c++17 bom.cpp -o bom && ./bom

You should see the three parts printed in order. This printed chain is your bill of materials; the next sections add and remove parts as the design changes on site.

Insert at the beginning

Adding to the front is the cheapest move a linked list makes. You point the new node's next at the current head, then move the head to the new node. No existing node moves. This is the same reason a builder staples the newest change note to the top of the clipboard: it is one action, no matter how thick the stack.

#include <iostream>
#include <string>

struct Part {
    std::string name;
    int qty;
    Part* next;
};

// add a node at the front; returns the new head
Part* insertFront(Part* head, std::string name, int qty) {
    Part* node = new Part{name, qty, head};   // point next at old head
    return node;                              // node is the new head
}

void printList(Part* head) {
    for (Part* p = head; p != nullptr; p = p->next) {
        std::cout << p->qty << " x " << p->name << std::endl;
    }
}

int main() {
    Part* head = nullptr;
    head = insertFront(head, "Bolts", 8);
    head = insertFront(head, "Ridge beam", 1);
    head = insertFront(head, "Rafter", 2);   // newest ends up first
    printList(head);
    return 0;
}

Insert at the end

Adding to the end is more work: with only a head pointer you must first walk to the last node (the one whose next is nullptr), then hang the new node off it. If the list is empty, the new node simply becomes the head.

#include <iostream>
#include <string>

struct Part {
    std::string name;
    int qty;
    Part* next;
};

// add a node at the end; returns the head
Part* insertEnd(Part* head, std::string name, int qty) {
    Part* node = new Part{name, qty, nullptr};
    if (head == nullptr) {
        return node;              // empty list: new node is the head
    }
    Part* p = head;
    while (p->next != nullptr) {  // walk to the last node
        p = p->next;
    }
    p->next = node;               // hang the new node off the end
    return head;
}

void printList(Part* head) {
    for (Part* p = head; p != nullptr; p = p->next) {
        std::cout << p->qty << " x " << p->name << std::endl;
    }
}

int main() {
    Part* head = nullptr;
    head = insertEnd(head, "Rafter", 2);
    head = insertEnd(head, "Ridge beam", 1);
    head = insertEnd(head, "Bolts", 8);   // stays in the order added
    printList(head);
    return 0;
}

Search the list

To answer "is this part on the bill?" you traverse and compare each node's data. Return true the moment you find it; if you reach nullptr you never found it, so return false. A menu works the same way: to check whether the kitchen still lists jollof rice you read down the card until you find it or run out.

#include <iostream>
#include <string>

struct Dish {
    std::string name;
    Dish* next;
};

// true if a dish with this name is on the menu
bool contains(Dish* head, std::string target) {
    for (Dish* p = head; p != nullptr; p = p->next) {
        if (p->name == target) {
            return true;
        }
    }
    return false;
}

int main() {
    Dish* jollof = new Dish{"Jollof rice", nullptr};
    Dish* fufu   = new Dish{"Fufu", nullptr};
    jollof->next = fufu;
    Dish* menu = jollof;

    std::cout << "Jollof rice? " << contains(menu, "Jollof rice") << std::endl;
    std::cout << "Pizza? "       << contains(menu, "Pizza")       << std::endl;

    delete jollof;
    delete fufu;
    return 0;
}

Delete a node

To remove a part you re-route the pointer that leads to it: make the node before it point to the node after it, then delete the removed node so its memory goes back. The special case is deleting the head, since no node points to it; then you just move the head forward.

#include <iostream>
#include <string>

struct Part {
    std::string name;
    int qty;
    Part* next;
};

// remove the first node whose name matches; returns the head
Part* removePart(Part* head, std::string name) {
    if (head == nullptr) {
        return nullptr;
    }
    if (head->name == name) {        // deleting the head
        Part* rest = head->next;
        delete head;
        return rest;
    }
    Part* p = head;
    while (p->next != nullptr && p->next->name != name) {
        p = p->next;                 // stop with p just before the target
    }
    if (p->next != nullptr) {        // found it
        Part* gone = p->next;
        p->next = gone->next;        // route around the removed node
        delete gone;
    }
    return head;
}

void printList(Part* head) {
    for (Part* p = head; p != nullptr; p = p->next) {
        std::cout << p->qty << " x " << p->name << std::endl;
    }
}

int main() {
    Part* head = new Part{"Rafter", 2, nullptr};
    head->next = new Part{"Ridge beam", 1, nullptr};
    head->next->next = new Part{"Bolts", 8, nullptr};

    head = removePart(head, "Ridge beam");   // scrap the ridge beam line
    printList(head);
    return 0;
}

Reverse the list

Reversing flips every arrow. You walk the chain with three pointers: prev (the part already flipped), curr (the one you are on), and next (saved before you overwrite the link, or you lose the rest of the chain). At each step you point curr->next back at prev, then slide all three forward. When curr falls off the end, prev is the new head.

#include <iostream>
#include <string>

struct Stop {
    std::string name;
    Stop* next;
};

// flip every pointer; returns the new head
Stop* reverse(Stop* head) {
    Stop* prev = nullptr;
    Stop* curr = head;
    while (curr != nullptr) {
        Stop* next = curr->next;   // save the rest before overwriting
        curr->next = prev;         // flip this arrow
        prev = curr;               // slide prev forward
        curr = next;               // slide curr forward
    }
    return prev;                   // prev is the last node we saw
}

void printTour(Stop* head) {
    for (Stop* p = head; p != nullptr; p = p->next) {
        std::cout << p->name;
        if (p->next != nullptr) std::cout << " -> ";
    }
    std::cout << std::endl;
}

int main() {
    // a tourist route: Victoria Falls -> Hwange -> Great Zimbabwe
    Stop* a = new Stop{"Victoria Falls", nullptr};
    Stop* b = new Stop{"Hwange", nullptr};
    Stop* c = new Stop{"Great Zimbabwe", nullptr};
    a->next = b;
    b->next = c;
    Stop* head = a;

    printTour(head);
    head = reverse(head);
    printTour(head);   // the tour now runs the other way

    delete a;
    delete b;
    delete c;
    return 0;
}

List versus array

An array is a single unbroken block of slots, numbered from zero. That layout is its strength and its weakness. Because the slots sit next to each other, jumping to slot 500 is instant. But inserting or deleting in the middle means shifting every slot after it to close or open the gap. A linked list is the opposite: reaching the middle means walking from the head one node at a time, but once you are there, splicing a node in or out is a couple of pointer changes and nothing else moves.

JobArrayLinked list
Reach the Nth itemInstant (jump to the slot)Walk N nodes from the head
Insert or delete at the frontShift every other itemA couple of pointer changes
Insert or delete in the middleShift the items after itA couple of pointer changes
Grow the sizeMay need a whole new blockJust new one more node
Memory per itemJust the dataData plus one pointer per node
Layout in memoryOne contiguous blockScattered, joined by pointers

The rule of thumb: pick an array when you mostly read by position and the size is steady; pick a linked list when you add and remove a lot, especially at the ends, and you rarely need to jump straight to the middle. A bill of materials that changes all through the build is a natural linked list.

Challenge: spot the bug

A student writes this reverse loop. It compiles and runs, but the list comes back with only one node. What went wrong?

Stop* prev = nullptr;
Stop* curr = head;
while (curr != nullptr) {
    curr->next = prev;     // flips the arrow first...
    prev = curr;
    curr = curr->next;     // ...but next now points at prev
}
return prev;

Answer: the line curr->next = prev; overwrites the link to the rest of the chain before it is saved. The next line then reads the already-flipped curr->next, so curr jumps backward instead of forward and the walk ends early. The fix is to save the next node in a temporary first: Stop* next = curr->next; at the top of the loop, and advance with curr = next;.

Exam questions

Q1. Explain what a singly linked list is, and state two advantages it has over an array.

Model answer

A singly linked list is a chain of nodes. Each node holds a piece of data and a single pointer to the next node; the last node's pointer is nullptr. A separate head pointer marks the first node, and the list is read by traversing from the head, following each next until nullptr. The nodes need not sit together in memory; the pointers alone hold the order.

Two advantages over an array: (1) inserting or deleting, especially at the front, costs only a few pointer changes, whereas an array must shift the other elements to open or close the gap; (2) the list grows one node at a time with new and needs no fixed size up front, whereas an array may have to be re-allocated into a larger block when it fills.

Q2. Write a C++ function that searches a singly linked list of integers for a target value and returns true if it is present, otherwise false.

Model answer

struct Node {
    int value;
    Node* next;
};

bool contains(Node* head, int target) {
    for (Node* p = head; p != nullptr; p = p->next) {
        if (p->value == target) {
            return true;      // found it, stop early
        }
    }
    return false;             // reached the end without a match
}

The loop starts at the head and follows next to the end. It returns true as soon as a node matches; if it falls off the end at nullptr the value was never there, so it returns false.

Q3. Write functions to insert a new node at the beginning of a singly linked list, and to insert a new node at the end. Each returns the head.

Model answer

struct Node {
    int value;
    Node* next;
};

// insert at the beginning: cheapest case, no walking
Node* insertFront(Node* head, int value) {
    Node* node = new Node{value, head};   // point next at old head
    return node;                          // new node becomes the head
}

// insert at the end: walk to the last node first
Node* insertEnd(Node* head, int value) {
    Node* node = new Node{value, nullptr};
    if (head == nullptr) {
        return node;                      // empty list
    }
    Node* p = head;
    while (p->next != nullptr) {
        p = p->next;                      // stop on the last node
    }
    p->next = node;
    return head;
}

Inserting at the front is one step: the new node points at the old head and becomes the head. Inserting at the end must first traverse to the node whose next is nullptr, then attach there; the empty list is handled as a special case where the new node is the head.

Q4. Write a C++ function to reverse a singly linked list, returning the new head. Explain why a temporary pointer is needed inside the loop.

Model answer

struct Node {
    int value;
    Node* next;
};

Node* reverse(Node* head) {
    Node* prev = nullptr;
    Node* curr = head;
    while (curr != nullptr) {
        Node* next = curr->next;   // save the rest of the chain
        curr->next = prev;         // flip this node's pointer
        prev = curr;               // advance prev
        curr = next;               // advance curr
    }
    return prev;                   // prev is the new head
}

The temporary next is needed because the line curr->next = prev; overwrites the pointer to the remaining nodes. Without saving it first, there would be no way to reach the rest of the list, and the walk would stop after one node. When the loop ends, curr is nullptr and prev holds the last node visited, which is now the front.

Q5. Write a complete C++ program that builds a three-node linked list of strings and prints each node on its own line.

Model answer

#include <iostream>
#include <string>

struct Node {
    std::string value;
    Node* next;
};

int main() {
    // build three nodes and link them
    Node* n1 = new Node{"Rafter", nullptr};
    Node* n2 = new Node{"Ridge beam", nullptr};
    Node* n3 = new Node{"Bolts", nullptr};
    n1->next = n2;
    n2->next = n3;
    Node* head = n1;

    // traverse and print
    for (Node* p = head; p != nullptr; p = p->next) {
        std::cout << p->value << std::endl;
    }

    delete n1;
    delete n2;
    delete n3;
    return 0;
}

The three nodes are created with new, joined by setting each next, and head is aimed at the first. The for loop traverses from the head to nullptr, printing one node per line, then each node's memory is returned with delete.
