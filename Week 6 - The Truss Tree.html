The Truss Tree

Unit 10: Trees. A cut-list is flat, but a truss branches. A binary tree gives every node two children, left and right. A binary search tree keeps smaller values left and larger right, so search walks straight down one side: about O(log n) steps for a balanced tree, not O(n).

Day 1 · Binary tree nodes

A node is a value with a left and a right

A binary tree is built from nodes. Each node holds a value and two links, left and right, each pointing to another node or to nothing (NULL). The top node is the root, the king-post of the truss.

A node with no children is a leaf, a rafter tip where the frame ends. "Binary" just means two children at most. Today you build three nodes by hand and hang two off the root, so you can see a node IS just a struct that points at two more.

Day 2 · Build a BST

Insert by stepping left or right until you fall off

A binary search tree (BST) adds one rule to every node: everything in its left branch is smaller, everything in its right branch is larger. That ordered property is what makes the tree searchable.

To insert a value, start at the root and compare. Smaller means step left, larger means step right. Keep stepping until you reach an empty spot (NULL), then hang the new node there. The rule holds itself together: each insert lands exactly where a later search would look.

The code

insert calls itself on root->left or root->right, walking down one branch until it hits NULL. That is the same recursion idea as Week 5 quicksort, aimed down a tree.

Day 3 · In-order traversal

Left, self, right prints the tree sorted

A traversal visits every node in some order. In-order does three moves at each node, always in this sequence: walk the left branch, visit this node, walk the right branch.

On a BST that sequence lands the values smallest to largest, so in-order prints the tree sorted for free. Picture reading the truss left to right along the bottom chord: you pass under every joint in ascending order.

Day 4 · Pre-order & post-order

Same three moves, different sequence, different job

Two more traversals reorder the same three moves. Pre-order visits this node first, then left, then right. Post-order visits left, then right, then this node last.

Pre-order sees a parent before its children, which is how you copy a truss: set the king-post before the rafters that hang off it. Post-order sees children before the parent, which is how you take a truss down or free a tree: clear both branches before removing the joint above them.

Day 5 · Depth & height

How tall the truss stands sets what search costs

The depth of a node is how many steps down it sits from the root. The height of the tree is the depth of its lowest leaf, the longest run of steps from root to a tip.

Compute it bottom-up: an empty tree has height -1, a lone root has height 0, and any node's height is 1 plus the taller of its two branches. Height matters because it is what a search may cost: a short, bushy truss searches fast, a tall lopsided one does not.

Day 6 · Tie it together

The truss AS a tree: search down one side, ~O(log n)

Search reuses the insert rule. At each node, if the target is smaller go left, if larger go right, if equal you found it. Every step drops a whole branch, so a search costs the tree's height, not its node count.

A balanced tree of n nodes stands about log2(n) tall, so search touches ~20 joints in a million, not a million. That is the same O(log n) win as binary search from Week 5, but a tree also stays cheap to insert into. The truss AS a tree: king-post is the root, rafters branch left and right, and a search walks straight down one side of the frame to its joint.
